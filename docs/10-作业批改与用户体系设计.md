> 版本 v0.1 ｜ 2026-09-22 ｜ 状态：待评审（本文档只定方案，未动代码）
> 关联文档：01 需求（§1.3 非目标需改口）、02 架构（§6 目录 / §7 配置）、03 详细设计（§6 DDL）、04 API（§1 总览 / §8 ID 规则）、06 前端规范、07 开发计划（本方案作为 M6）、09 数据大屏与学习路径（M5，弱联调点）
> 来源：导师 2026-09-21 追加要求——「上传图片、自动批改可调用大模型，展示丰富一些；注册这些都弄上」。定位：**给导师展示用的 demo，设计越简单能跑越好。**

## 0. 先给结论

| 功能 | 本质 | 工作量 | 主要风险 |
|---|---|---|---|
| **作业批改**（图片上传 + 大模型批改） | 新增一条有状态的长任务流水线（30–90s） | 约 3.5 人天 | 视觉模型不可用/额度耗尽；模型 JSON 输出不稳 |
| **注册登录** | 一张 users 表 + 一张 token 表 + HttpOnly Cookie | 约 1 人天 | 与 01 §1.3「不做用户登录」的旧口径冲突（需改口） |

三条主线判断：

1. **批改必须给标准答案。** 题目与参考答案随提交一起带上（预置 3 题 + 现场自定义）。没有参考答案的"自由批改"会把"模型自己算错"记成"学生错"，导师追问一句就露馅；有参考答案后模型只做"对照与点评"，是它擅长的活。
2. **长任务走轮询，不走 SSE。** 批改没有逐 token 的价值，只有阶段进度（识别中→评分中→关联课件）；轮询（1.5s）天然可刷新恢复、断线无感，且与现有 documents 的 `pending→…→failed` 状态机模式完全一致——照抄即可，是全项目最省代码的一条路。
3. **登录只保护"个人数据"（作业），不拦全站。** 演示主线（问答/图谱/大屏）不因登录状态而翻车；注册的"用处"在作业链路上天然可见（报告归属人、我的作业列表）。全站强制登录留作 P1 配置位，导师若坚持再加约 0.3 天。

视觉模型**单独配置** `VISION_MODEL`（不假设现有 DeepSeek 文本模型有视觉能力）；未配置或调用失败时降级为"文本批改"（手打题目+答案），保证演示永远有东西可看。

## 1. 现状盘点（写方案前已核对）

**已有可复用能力**

- `ingestion_service.save_upload()` + `asyncio.create_task(self.ingest(doc_id))`（ingestion_service.py:102）：长任务 + 落盘 + `documents.status` 状态机 + 失败中文文案——作业流水线**照抄这个模式**，不发明新机制。
- `RAGService.retrieve(query, mode=None) -> {chunks:[{doc_name, chunk_id, snippet}]}`（rag_service.py:102，Task 3.2 落地）：linking 阶段取"课件依据"直接复用。
- `GET /api/health?check_llm=1` 深探测 + 前端状态点：扩一个 `vision` 字段（只在配置了 `VISION_MODEL` 时探测），演示前自检多一道保险。
- 上传校验先例：扩展名白名单 + `UPLOAD_MAX_MB` + multipart（documents.py:16）；前端 `library.js:69` 已有 FormData 上传写法。
- `error_response(status, code, message, detail)`（app/api/common.py）统一错误体；04 §8 的 ID 前缀规则（本期增补 `u_` / `h_`）。

**关键缺口**

- 无用户表、无凭据机制；且 01 §1.3 明确写了"不做用户登录、权限、多租户"——**本方案要求改口**为"不做权限体系与多租户；仅提供单机演示级注册登录"（Task 6.9 同步 01）。
- 无视觉模型调用代码：`lightrag_factory.llm_model_func` 是 LightRAG 内部使用的纯文本 chat，不适合塞图片；需新增独立 VL 客户端（httpx 直连 OpenAI 兼容 `image_url` 格式，**不引新依赖**）。
- 无图片类上传校验（现有上传是文档解析链路，图片要的是 magic bytes + 压缩 + 原图保留供报告展示）。

## 2. 用户体系（最小可用）

### 2.1 凭据与存储

- 密码：**PBKDF2-HMAC-SHA256**（`hashlib.pbkdf2_hmac`，200,000 迭代，16B 随机盐），标准库零依赖；落库只存 `password_hash` + `salt`，明文不进日志（沿用 NFR-SEC-01 纪律）。
- 会话：`secrets.token_urlsafe(32)` 存 `auth_token` 表，浏览器侧 **HttpOnly Cookie**（`cnr_token`，`SameSite=Lax`，7 天，不设 `Secure`——局域网 http 演示）。
  - **为什么用独立 token 表而不是 users 表加一列**：演示时手机与电脑可能同时登录同一账号，单列 token 会把前一个设备挤下线，是现场翻车点；独立表多写 3 行代码换掉这个风险。
- 登出 = 删 token 行 + 清 cookie；过期 token 读取时惰性校验，不做后台清理任务。

```sql
CREATE TABLE IF NOT EXISTS users (
  user_id       TEXT PRIMARY KEY,   -- 'u_' + 8hex
  username      TEXT NOT NULL UNIQUE,
  password_hash TEXT NOT NULL,
  salt          TEXT NOT NULL,
  created_at    TEXT NOT NULL,
  last_login_at TEXT
);
CREATE TABLE IF NOT EXISTS auth_token (
  token      TEXT PRIMARY KEY,      -- secrets.token_urlsafe(32)
  user_id    TEXT NOT NULL,
  created_at TEXT NOT NULL,
  expires_at TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_token_user ON auth_token(user_id);
```

### 2.2 校验与边界

| 项 | 规则 |
|---|---|
| username | 3–20 字符，字母/数字/下划线/中文；重复 → 409 `USERNAME_TAKEN` |
| password | 6–64 字符（不强制复杂度，demo 定位） |
| 注册 | 成功即自动登录（同一响应 Set-Cookie），展示一次"注册→已在用"的连贯感 |
| 登录失败 | 统一 401「用户名或密码错误」，不区分"用户不存在" |
| 未登录访问受保护端点 | 401 `UNAUTHORIZED`；前端捕获后弹登录模态 |

**明确不做**：邮箱/短信验证、找回密码、第三方登录、角色权限、注册频率限制（单机演示，无对外暴露）。

### 2.3 保护范围

挂 `require_user` 依赖（不是全局中间件）的端点：`/api/homework` 全部 + `/api/auth/me` + `/api/auth/logout`。其余端点全部保持匿名：问答、图谱、大屏、知识库管理、`/api/homework/tasks`（题目列表无隐私）。

理由：演示主线零风险；作业必须归属人，是登录的"用处"可视化。

- `AUTH_REQUIRED`（默认 false）**本项目不开**，仅作 P1 预案：若导师要求"必须登录才能进系统"，加全局中间件 + 白名单（`/api/auth/*`、静态资源、`/screen`）约 0.3 天。
- 现有 5 视图与 TABS 逻辑不动，只在数组尾部追加。

### 2.4 前端

- **顶栏用户区**（健康点左侧）：未登录显示「登录 / 注册」按钮（打开模态）；已登录显示用户名首字头像 + 下拉（我的作业 / 退出登录）。
- `components/auth-modal.js`：登录/注册双 Tab 合一模态，字段仅用户名/密码[/确认密码]，回车提交，错误行内红字，成功后更新 `Store.user` 并关闭。
- 401 全局处理：`api.js` 的 `getJSON/postJSON` 遇到 401 置 `Store.user = null` 并抛带 `status` 的错误；作业页捕获后弹模态，**保留已选图片与表单内容**（不丢用户输入）。

## 3. 作业批改（图片上传 + 大模型批改）

### 3.1 演示故事与验收标准

1. 顶栏注册一个账号（如 `2023001`）→ 自动登录；
2. 进「作业批改」页：题目下拉选预置题「子网划分练习（10 分）」，上传 1–3 张手机拍的手写作业照片（手机端可直接调后置摄像头）；
3. 点「提交批改」→ 进度条走 `识别中 → 评分中 → 关联课件依据 → 完成`（30–90s）；
4. 报告页：分数环 + 等级 + 逐题卡片（对/半对/错 + 得分 + 点评 + 学生答案 vs 参考要点）+ 弱知识点标签 + 课件依据 + 复习建议 + 原图缩略图；
5. 弱知识点标签 → 跳学习路径（M5 已做）或降级跳图谱搜索；
6. 大屏（M5）"作业批改"数字卡 +1、平均分更新、跑马灯出现"最新批改：82 分"。

验收写成可判定的三条：

1. 3 张照片从提交到出报告 ≤120s；中途刷新/关掉标签页再打开，进度继续推进（状态在库里）；
2. 报告任一字段缺失不影响其余字段渲染（前端逐字段兜底）；模型 JSON 解析失败时展示"模型原始输出"而非白屏；
3. 未登录时提交 → 弹登录模态，登录后原表单（图片+题目）不丢。

### 3.2 数据模型（1 张表）

```sql
CREATE TABLE IF NOT EXISTS homework (
  hw_id      TEXT PRIMARY KEY,   -- 'h_' + 8hex
  user_id    TEXT NOT NULL,
  task_code  TEXT,               -- 预置题目 code；自定义为 NULL
  task_title TEXT NOT NULL,      -- 展示用标题
  question   TEXT,               -- 题干快照（预置题的副本或现场手填）
  ref_answer TEXT,               -- 参考答案快照（可空 = 无参考答案模式）
  max_score  REAL DEFAULT 100,
  images     TEXT NOT NULL,      -- JSON: ["homework/<hw_id>/1.jpg", ...]
  status     TEXT NOT NULL,      -- pending | grading | linking | done | failed
  stage_note TEXT,               -- 中文进度文案，前端直接显示
  report     TEXT,               -- JSON 批改报告（§3.4），解析失败时存模型原文
  score      REAL,               -- 与 max_total 冗余出来给列表/大屏用
  max_total  REAL,
  mode       TEXT,               -- vision | text
  error      TEXT,
  created_at TEXT NOT NULL,
  graded_at  TEXT,
  elapsed_ms INTEGER
);
CREATE INDEX IF NOT EXISTS idx_hw_user ON homework(user_id, created_at);
```

- **不建 homework_task 表**：预置题目是常量（§3.3），题干/参考答案在提交时**快照进 homework 行**——题目以后改了，历史报告不受影响，语义反而更对。
- **启动自愈**：lifespan 里 `UPDATE homework SET status='failed', error='服务重启，请重新提交' WHERE status IN ('grading','linking')`（与 documents 悬挂处理同款），避免重启后永远卡在"批改中"。

### 3.3 预置题目（常量，不建表）

`app/homework/tasks.py` 放 3 道题，覆盖三种题型，恰好演示"图片识别 + 对照参考答案 + 逐题点评"：

| code | 标题 | 类型 | 说明 |
|---|---|---|---|
| `subnet-1` | 子网划分练习（10 分） | 计算题 | 「将 192.168.10.0/24 划分为 /27，写出第 2 个子网的网络/广播/可用主机范围」 |
| `delay-1` | 时延计算（10 分） | 计算题 | 「1000 字节分组经 1Mbps 链路，发送时延是多少？含推导」 |
| `hs-1` | 概念简答：三次握手（10 分） | 概念题 | 「为什么需要三次握手？两次为什么不行？」 |

- 题干与参考答案实现时**与课件/教材口径逐条核对**（第 4/5 章 pptx 已在库），避免与课件冲突。
- 自定义入口：题目下拉选「自定义」→ 出现题干 / 参考答案 / 满分三个输入框；参考答案留空 = 无参考答案模式，报告标注「未提供参考答案，点评仅供参考」。

### 3.4 批改报告结构（严格 schema）

```json
{
  "mode": "vision",
  "total": { "score": 8.5, "max": 10, "level": "良", "summary": "一句话总评" },
  "questions": [
    { "no": 1, "title": "子网划分", "verdict": "partial", "score": 8.5, "max": 10,
      "student_answer": "192.168.10.32/27…", "ref_answer": "192.168.10.64/27…",
      "comment": "网络地址正确；广播地址用了 /24 的 .255，应为 .95",
      "kp": ["子网掩码", "广播地址"] }
  ],
  "weak_kps": ["广播地址计算"],
  "suggestions": ["可用主机范围 = 网络号+1 ~ 广播-1"],
  "evidence": [ { "kp": "广播地址计算", "doc": "第4章-网络层.pptx", "snippet": "…" } ],
  "image_notes": []
}
```

- `verdict ∈ {correct, partial, wrong, unreadable}`；`0 ≤ score ≤ max`，后端校验并 clamp。
- **总分一律以逐题求和为准**（后端算，不信模型自报的 total）——这是"分数对不上"被追问时唯一站得住的算法，且可逐题核对。
- `evidence` 由 linking 阶段填充（模型不产出，避免凭空引用课件）。
- prompt 要求**先写评分理由再给分**（reason first），报告展示理由而非"算法黑箱"。

### 3.5 流水线（后台任务，照抄 ingestion 模式）

```
POST /api/homework
 ① 校验：登录 → 张数 ≤ HOMEWORK_MAX_IMAGES、单张 ≤ HOMEWORK_MAX_MB、magic bytes ∈ {jpeg,png,webp}
 ② 落盘 data/homework/<hw_id>/1.jpg… → 插 homework(status=pending, stage_note='已收到作业，排队批改…')
 ③ asyncio.create_task(grade(hw_id)) → 202 {"hw_id","status":"pending"}

grade(hw_id):
 ④ status=grading（'正在识别作业照片并批改…'）：图片 → base64 data URL → VL 调用（httpx，超时 HOMEWORK_TIMEOUT）
 ⑤ JSON 解析失败 → 追加"只输出 JSON"指令重试一次 → 再失败 status=failed（error='模型输出无法解析，请重试'，report 存原文供展示）
 ⑥ 校验 + clamp + 逐题求和定总分 → 落 report / score / max_total
 ⑦ status=linking（'正在关联课件依据…'）：weak_kps 取前 3 → RAGService.retrieve() 各取 ≤2 片段 → 补 evidence；任一失败忽略，不阻塞
 ⑧ status=done, graded_at, elapsed_ms
任一异常 → failed + 中文分类文案（鉴权失败 / 超时 / 网络不可达 / 解析失败）
```

- 阶段↔百分比（前端映射，后端只给 status + stage_note）：pending 5% / grading 55% / linking 85% / done 100%。
- VL 客户端 `app/homework/vl_client.py`：httpx POST `{VISION_BASE_URL}/chat/completions`，content 数组 = `[{type:"text"},{type:"image_url","image_url":{"url":"data:image/jpeg;base64,…"}}…]`（OpenAI 兼容格式，与 `llm_model_func` 同款直连，**不引新依赖**）。
- **文本兜底**：`VISION_MODEL` 未配置，或提交 0 张图只有手打答案 → `mode=text`，prompt 只带题干+参考答案+学生答案，走 `LLM_MODEL`。演示现场视觉模型不可用时仍有完整闭环。

### 3.6 图片策略

- **前端压缩**：canvas 长边 2000px、JPEG q0.85（手机原图 4–8MB → 约 300–800KB；2000px 下 11pt 手写仍可读，1600 风险偏大）；压缩异常则原图直传。
- 后端 magic bytes 校验（扩展名只作提示）。
- **原图保留**：报告要展示学生作业照片本身——缩略图条 + 点击灯箱放大。
- 访问走 `GET /api/homework/{hw_id}/image/{idx}`（FileResponse + 归属校验），**不把 data/ 挂成静态目录**。
- 存储 `data/homework/<hw_id>/`，随 `data/` 目录迁移（NFR-DEP-03）；不做自动清理（演示量级，P2 再提）。

### 3.7 前端（"展示丰富"主要花在这里）

`views/homework.js`（新 Tab「作业批改」，插在「知识库管理」前）：

- 左栏表单：题目下拉（3 预置 + 自定义）/ 自定义题干+参考答案 / 多图上传（拖拽 + 缩略图预览 + 单张删除）/ 「提交批改」；手机端上传按钮加 `capture="environment"` 直接调后置摄像头。
- 右栏报告 `components/grade-report.js`：
  - 分数环（纯 CSS `conic-gradient`，不新增 ECharts 实例）+ 等级徽标 + 用时 + mode 标注（图片批改/文本批改）；
  - 逐题卡片：verdict 徽标（绿=对 / 琥珀=半对 / 红=错 / 灰=无法识别）+ 得分 + 点评 + 折叠的「学生答案 vs 参考要点」；
  - 弱知识点 chips → 点击跳 `#/path?kp=`（M5 存在时）否则 `#/graph?q=`；
  - 课件依据卡（复用 source-card 样式）+ 建议列表 + 固定声明「批改结果仅供教学参考」；
  - 原图缩略图条 + 灯箱。
- 轮询：提交后 1.5s 间隔 GET 详情直到 done/failed；视图用 v-show 常驻，切走再切回继续显示；failed 给「重新提交」按钮。
- 历史：报告区顶部「我的作业」列表（需登录；未登录显示引导文案）。
- 手机端单列布局（表单在上、报告在下）。

## 5. 配置项（.env 与 02 §7 增补）

| 变量 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `VISION_MODEL` | 否 | 空 | 视觉模型名（需支持 OpenAI 兼容 `image_url`）。空 = 仅文本批改。已定百炼 qwen-vl 系列（`qwen3-vl-plus` / `qwen-vl-max-latest` 等，以控制台实际可用名为准） |

| `HOMEWORK_MAX_MB` | 否 | 5 | 单张图片大小上限 |
| `HOMEWORK_MAX_IMAGES` | 否 | 6 | 单次提交图片张数上限 |
| `HOMEWORK_TIMEOUT` | 否 | 300 | 单次批改超时秒 |
| `AUTH_TOKEN_TTL_HOURS` | 否 | 168 | 登录有效期 |

`VISION_*` 三项独立于 `LLM_*` 且逐项回退：现有文本模型普遍不支持视觉，独立配置才能"只换视觉模型、不动建库模型"；回退保证只配一个厂商时也能用。
