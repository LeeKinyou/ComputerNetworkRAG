## 1. 项目背景与目标

### 1.1 背景

导师需要一个可现场演示的智能体系统，展示面包含三块内容：

1. **计算机网络课程知识图谱**（课程知识结构的可视化）；
2. **RAG 课程问答**（基于课件/教材/讲义的可信回答，带来源）；
3. **ReAct 智能体问答与简单操作**（智能体自主调用与计算机网络相关的工具，且**每一步操作过程可视化**）。

此前曾使用开源 LightRAG 完成过原型且检索效果可接受，但代码遗失需全部重做。

### 1.2 目标

- 交付一个**演示级 MVP**：核心功能闭环、前端精致美观、现场启动稳定。
- **部署极简**：单进程、不做前后端分离、不依赖外部数据库/中间件，Windows 笔记本可直接运行，整体可拷贝迁移。
- **可扩展**：文档格式、智能体工具、存储后端三类扩展点全部以"注册表 + 接口"预留，MVP 只实现最简实现。

### 1.3 非目标（明确不做）

- 不做用户登录、权限、多租户与多人协作（M5 及之前完全无账号；M6 的用户体系与作业批改已有设计稿，见 10 号文档，尚未实现）；
- 不做生产级高并发与水平扩展；
- 不做复杂版面还原与扫描件 OCR（扫描版 PDF/纯图片 PPT 无文字层，解析失败并给出友好提示）；
- 不做对任意外部主机的端口扫描、批量 ping 等具有安全风险的能力（网络探测类工具设白名单与速率限制）。

## 2. 角色与使用场景

| 角色 | 场景 |
|---|---|
| 演示者（学生本人） | 启动系统；课前上传/更新课程材料并建库；现场切换页面讲解、发起问答 |
| 观看者（导师/同学） | 观看知识图谱、RAG 回答与引用、智能体逐步推理与工具调用过程 |
| 维护者（后续迭代） | 通过预留接口新增文档格式、新增网络工具、替换存储后端 |

### 2.1 典型演示路径

1. 打开"概览页"：展示知识库规模（文档数、实体数、关系数）；
2. 进入"知识图谱页"：浏览"计算机网络"实体关系网络，点击实体查看详情与来源；
3. 进入"RAG 问答页"：提问课程概念题，流式出答案并展示引用片段，可切换 naive/local/hybrid 检索模式对比；
4. 进入"ReAct 智能体页"：提问需要"计算 + 查课件"的复合题，界面逐步渲染 思考→行动→观察 时间线，最后流式给出答案；
5. 进入"学习路径页"：按教材章节展开知识点先修图，系统给出从当前进度到目标知识点的最短学习顺序，已问过的知识点标记触达；
6. 投屏时切"数据大屏"（`/screen`，新标签全屏）：核心指标、图谱、章节覆盖与实时动态轮播，3 米外可读；
7. （可选）"知识库管理页"现场上传一份新讲义并触发建库，展示增量更新。

## 3. 功能需求

编号规则：FR-模块-序号；优先级 P0=MVP 必做，P1=接口预留。

| FR-ING-02 | 支持上传 `.docx`，抽取段落与表格文本 | P0 |
| FR-ING-03 | 支持上传 `.pdf`，抽取文字层纯文本（不做 OCR，扫描件返回友好提示） | P1（已实现） |

| FR-ING-06 | 文档列表查看、删除、对单篇重建索引 | P0 |

### 3.4 ReAct 智能体（AGT）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-AGT-01 | 基于 OpenAI 兼容 Function Calling 实现 ReAct 循环（思考→行动→观察→…→最终回答），最大步数可配置（默认 6） | P0 |
| FR-AGT-02 | 每一步通过 SSE 实时推送：内容事件 thought / action / observation / token / final / error，另含 meta / step_start 控制事件，以及 P1 人工审批事件 interrupt / resumed（完整定义见 04 号文档 §6.2） | P0 |
| FR-AGT-03 | 前端以垂直时间线渲染每一步：思考（蓝）、工具调用含参数（橙）、观察结果含耗时与成败状态（绿/红） | P0 |
| FR-AGT-04 | 工具异常被捕获并作为 observation 回灌，循环不中断；最终失败发 error 事件并在界面标红，支持"重试本轮" | P0 |
| FR-AGT-05 | 完整 trace（每步类型、工具名、参数、结果、耗时）落 SQLite，历史运行可逐步回放 | P0 |
| FR-AGT-06 | 可在请求中指定本次启用的工具子集 | P1 |
| FR-AGT-07 | 支持中途"停止生成" | P1 |
| FR-AGT-08 | 人工审批节点：对标记 `requires_approval` 的工具，执行前中断并推送 interrupt 事件，人工可批准/修改参数/拒绝，随后从断点续跑（LangGraph interrupt + Checkpointer，thread_id=run_id） | P1 |

### 3.7 数据大屏（SCREEN）

面向投屏演示的第二终端，设计约束与取舍见 09 号文档 §2、02 号文档 ADR-7。

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-SCREEN-01 | `/screen` 独立深色页面：1920×1080 固定画布 + JS 等比缩放，投影仪与笔记本显示同一构图，不做响应式重排 | P1（已实现） |
| FR-SCREEN-02 | 一次 `/api/screen/overview` 取回全部聚合数据（十个字段），**每个字段独立容错**：单字段取数或渲染失败只降级自己，其余照常 | P1（已实现） |
| FR-SCREEN-03 | 7 张指标卡（文档/实体/关系/分块/会话/运行 + 知识点触达覆盖率）与 6 张图（中央图谱、实体类型玫瑰、14 日趋势、工具雷达、章节覆盖、高频实体横条）+ 底部实时动态轮播 | P1（已实现） |
| FR-SCREEN-04 | 双周期轮询：总览 30s、中央图谱 5min（全量力导重排代价高）；取数失败后 15s 重试 | P1（已实现） |
| FR-SCREEN-05 | 3 米外可读：全站字号下限 16px；中央图谱按度数截取前 300 节点作投屏掉帧护栏 | P1（已实现） |
| FR-SCREEN-06 | 中央图谱聚焦轮播：每 8s 换一类实体并高亮其邻接 | P1（已实现） |

### 3.8 学习路径（PATH）

把"问答"升级为"学得会"：知识点先修图 + 触达记录 → 可解释的学习顺序。设计见 09 号文档 §3–§4。

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-PATH-01 | 从已建库图谱物化课程知识点：`knowledge_node`（知识点归一 + 按来源 chunk 文件路径多数投票归章，未归章的不进图）与 `prereq_edge`（有向先修边） | P1（已实现） |
| FR-PATH-02 | 构建过程离线执行（`scripts/build_learning_path`），逐章用 LLM 把图谱实体归并为教材知识点，支持单章与全量、可续跑且幂等 | P1（已实现） |
| FR-PATH-03 | `#/path`：章节下拉只列真正有知识点的章；先修图按最长路径分层布局，检测到环时安全降级 | P1（已实现） |
| FR-PATH-04 | 选定目标知识点后，反向 BFS 求先修闭包并给出从当前进度到目标的学习顺序（`/api/path/plan`） | P1（已实现） |
| FR-PATH-05 | 触达埋点：RAG 引用命中与智能体检索命中写 `knowledge_touch`（`via` 区分 rag_hit / agent_tool），驱动路径页"已触达"标记 | P1（已实现） |
| FR-PATH-06 | 知识点触达覆盖率上大屏：口径 = 已归章知识点中被触达过的**点**数 / 已归章知识点总数，与 `#/path` 完全同源，未回填 kp_id 的触达不计（宁少不假） | P1（已实现） |

## 4. 非功能需求（NFR）

| 编号 | 类别 | 要求 |
|---|---|---|
| NFR-DEP-01 | 部署 | 单个 uvicorn 进程同时提供静态前端与 API；`uv sync` 后 `uv run python main.py` 一条命令启动 |
| NFR-DEP-02 | 依赖 | 不安装 MySQL/Redis/Neo4j/ES 等任何需独立启动的服务；默认绑定 127.0.0.1 |
| NFR-DEP-03 | 迁移 | 整个项目（含 `data/`）可目录拷贝到另一台 Windows 机器，装依赖后直接运行 |
| NFR-PERF-01 | 性能 | 本地计算类工具单次响应 ≤100ms；SSE 首帧 ≤200ms；RAG/Agent 首 token 时间取决于 LLM API，界面须有加载与流式反馈，不得白屏 |
| NFR-PERF-02 | 规模 | 支持课程量级语料：文档 ≤200 篇、抽取实体 ≤2 万（LightRAG 默认文件存储可承受范围） |
| NFR-SEC-01 | 密钥 | LLM/Embedding 密钥只存在于 `.env`，不入库、不入日志、不进前端 |
| NFR-SEC-02 | 上传 | 扩展名白名单 + 大小限制 + 原始文件存于 `data/uploads/`，文件名做安全化处理 |
| NFR-SEC-03 | 网络工具 | 探测类工具统一超时（默认 3s）、目标白名单/本机限制、单次调用频率限制，禁止网段扫描 |
| NFR-MAINT-01 | 可扩展 | Parser、Tool、Storage 三类扩展点均为"抽象基类 + 注册表"，新增实现不改主流程 |
| NFR-UX-01 | 体验 | 全中文界面；所有异步操作有状态反馈；空态/错误态有明确文案；适配笔记本 1366×768 及以上分辨率 |
| NFR-REL-01 | 可靠 | 演示前可通过自检脚本/健康检查确认 LLM、索引、数据目录就绪；建库失败不影响已有数据 |

## 5. MVP 范围汇总

**P0 闭环**：md/txt/docx 建库 → 知识图谱浏览 → RAG 流式问答（hybrid + 引用）→ Agent 四工具（subnet/lpm/dns/course_rag）+ 六类事件步骤时间线 + trace 落库回放 → 概览统计 → 单进程启动。

**P1 已实现**：pdf/pptx 解析（pypdf 文字层提取 / python-pptx 按页抽取，不含 OCR）；M5 数据大屏（§3.7）与学习路径（§3.8）全链路——触达埋点、知识点物化与先修边构建、`/api/path` 读侧、`#/path` 页面、大屏覆盖率卡。

**P1 仅留接口**：packet/number/ping/http 工具、布局切换、停止生成、工具子集选择；大屏聚焦轮播时的自动平移（roam）、跨章节的整书路径规划。

**P2 远期方向**：Neo4j/Qdrant 存储切换、本地 Ollama 离线模型、多用户、PPT 版式还原。

## 6. 验收标准（演示验收 Checklist）

1. 全新机器按 08 号文档操作，30 分钟内完成环境准备并成功启动；
2. 上传 ≥3 份课程材料（含 1 份 docx），全部显示"已索引"，概览统计数字正确；
3. 知识图谱正确渲染，可搜索到指定实体（如"TCP"）并点开详情与来源；
4. RAG 页对课程概念题给出正确、带引用的流式回答；切换 hybrid/naive 结果存在可见差异；
5. Agent 页提问"192.168.10.137/27 属于哪个子网、网关一般设哪"类复合问题，时间线至少出现"思考→subnet_calculator→观察→思考→course_rag_query→观察→最终回答"，且计算结果正确（/27：网络地址 .128、广播 .159、可用 .129–.158）；
6. 断网或填错 key 时界面给出明确错误提示而非崩溃；
7. 刷新页面后历史会话与一次 Agent 运行 trace 可重新查看/回放；
8. 任务管理器中仅存在一个 Python 进程，无其他数据库/容器进程；
9. 概览页点"数据大屏"在新标签打开 `/screen`，1920 与 1366 下构图一致（等比缩放）；断开后端再恢复，页面不整屏白，取数失败的图保留占位文字、其余图照常刷新；
10. （前置：已执行 `scripts/build_learning_path`）学习路径页选章节可出分层先修图，点目标知识点能给出先修闭包与学习顺序；问答命中过的知识点在路径页标"已触达"，且大屏覆盖率卡的分子分母与路径页统计一致。

## 7. 假设与依赖

- 演示时可获得 OpenAI 兼容 API（如 DeepSeek）的可用密钥与网络；离线场景为 P2，配置位预留。
- 课程材料以文字型 md/docx/讲义为主，公式与扫描图片占比低。
- 开发与演示机器为 Windows 10/11；运行时锁定 Python 3.12，环境由 uv 管理（无需预装 Python，uv 可自动准备）。
