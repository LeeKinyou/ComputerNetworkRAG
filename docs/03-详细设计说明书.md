## 1. 模块职责清单

| 模块 | 文件 | 职责 | 不允许做的事 |
|---|---|---|---|
| 入口 | `main.py` | 组装 FastAPI、挂载 static、路由注册、启动/关闭生命周期（初始化 LightRAG 单例与 SQLite） | 不写业务逻辑 |
| 配置 | `app/config.py` | `Settings` 单例，读取并校验 `.env`，全局只从此处取配置 | 其他模块不得直接读环境变量 |
| 模型 | `app/schemas.py` | 请求/响应/SSE 事件的 Pydantic 模型 | 不含逻辑 |
| 文档接入 | `app/services/ingestion_service.py` | 保存上传文件、选 parser、清洗、调 LightRAG 入库、更新文档状态 | 不直接解析具体格式 |
| 解析器 | `app/parsers/*` | 各格式 → markdown 文本；注册到 `PARSER_REGISTRY` | 不调 LLM、不做切块 |
| RAG 服务 | `app/services/rag_service.py` | 封装 LightRAG 查询、模式校验、来源整理、回答流式化 | 不关心 HTTP/SSE |
| 图谱服务 | `app/services/graph_service.py` | 从 NetworkX 图导出节点/边、关键字过滤、实体子图；清洗与度数为公共函数供大屏复用 | 不直接读 LightRAG 内部文件 |
| 统计服务 | `app/services/stats_service.py` | `/api/stats` 与大屏 `stats` 字段共用的同一份核心统计 | 不各自拼 SQL，避免两处数字对不上 |
| 大屏服务 | `app/services/screen_service.py` | 一次性聚合十个字段供 `/api/screen/overview` | 单字段取数失败只降级自己，不整屏报错；不做业务写入 |
| 学习路径 | `app/services/path_service.py` | 写侧：物化知识点、抽校验先修边；读侧：分层布局、反向 BFS 先修闭包与学习顺序 | 读侧不碰 LightRAG、不调 LLM，只查 SQLite |
| 触达埋点 | `app/services/touch_service.py` | 把问答命中的实体名归一后写 `knowledge_touch` | 任何异常吞掉只记 warning，绝不打断问答主流程 |
| 路径构建脚本 | `scripts/build_learning_path.py` | 离线跑：物化归章 + 逐章 LLM 抽边 + 校验报告 | 不挂 HTTP 接口、不由页面按钮触发（一次调用几十秒且花钱） |
| Agent 服务 | `app/services/agent_service.py` | 创建会话/运行记录、驱动 builder/runner、事件落库、产出 SSE 与审批续跑 | 不实现推理细节 |
| Agent 构建 | `app/agent/builder.py` | 用 `create_agent` 组装模型、工具（经适配器）、system prompt、Checkpointer 与审批策略 | 不直接处理 HTTP/SSE |
| Agent 运行 | `app/agent/runner.py` | `astream` 驱动图运行，把 LangGraph 流事件映射为 SSE 事件，处理中断/恢复 | 不实现具体工具 |
| 工具注册 | `app/agent/registry.py` | 工具注册、schema 导出、统一执行（计时/异常捕获）、到 LangChain 工具的适配器 | 工具内部不互相调用 |
| 工具实现 | `app/agent/tools/*` | 一个文件一个工具，纯输入→输出 | 不持有全局状态 |
| LightRAG 工厂 | `app/rag/lightrag_factory.py` | 构建 LLM/embedding 异步函数、存储参数，返回进程级单例 | 不被工具直接 import |
| 仓储 | `app/storage/repository.py`、`sqlite_repo.py` | 文档/会话/消息/运行/步骤的增删查 | SQL 只出现在 sqlite_repo |
| 路由 | `app/api/*.py` | 请求校验、调 service、序列化、SSE 封装 | 不跨 service 编排 |

## 2. 关键时序

### 2.1 上传并建库

```
浏览器                api/documents        IngestionService      Parser        LightRAG        Repository
  │  multipart 上传       │                      │                  │              │               │
  │─────────────────────>│ 安全化文件名/限大小    │                  │              │               │
  │                      │─────────────────────>│ 写 uploads/，建文档记录(pending)   │──────────────>│
  │                      │                      │ get_parser(ext)──>│              │               │
  │                      │                      │ parse()──────────>│ markdown 文本 │               │
  │                      │                      │ 写 parsed/，状态 parsed           │               │
  │                      │                      │ ainsert(text)───────────────────>│ 切块/抽图谱    │
  │                      │                      │ 状态 indexed────────────────────────────────────>│
  │  GET /documents <────│<─────────────────────│                  │              │               │
```

### 2.2 RAG 问答（SSE）

```
client → api/rag: 校验 question/mode → rag_service.stream_answer()
  event: meta     {session_id, mode}
  event: sources  {items:[{doc_name, chunk_id, snippet}]}   # LightRAG 返回上下文后先发来源
  event: token    {delta} × N                                # 最终生成逐字
  event: final    {answer}
  （异常）event: error {message}
```

### 2.3 Agent 问答（SSE + 落库）

```
client → api/agent → agent_service.run()
  创建 agent_runs(running)，run_id 同时作为 LangGraph thread_id
  builder.build_agent() 取已编译图（含 checkpointer）
  async for event in runner.run_agent(agent, question, run_id, enabled_tools):
      sse_send(event)
      repo.append_step(run_id, event)    # thought/action/observation 落 agent_steps
      # interrupt 事件：当前流结束、状态留在检查点，等 /resume 端点同 thread 续跑
  结束 agent_runs(success/failed/waiting_approval)，消息写 messages
```

### 2.4 数据大屏（两条独立轮询线）

```
screen.js 启动 → fit() 等比缩放 → 两条线各自跑，互不阻塞：
  线 A 每 30s   GET /api/screen/overview
      screen_service.overview(repo)：十个字段逐个 _safe() 取数
        任一字段抛错 → 该字段回落占位值 + warning，其余照常返回 200
      → 7 数字卡 rAF 滚动 + 5 张统计图 setOption + 跑马灯
  线 B 每 5min  GET /api/graph?limit=500 → 按度数截前 300 节点 → 力导收敛后冻结坐标
      聚焦轮播每 8s dispatchAction 高亮一类实体的邻接（不重排，避免坐标与标签脱钩）
  任一条线取数失败 → 15s 后重试；已渲染的上一帧保留，不清屏
```

## 3. ReAct 详细设计

### 3.1 运行图（create_agent 预构建，不手工拼节点）

```
                AIMessage 含 tool_calls
   START → ┌──────────┐ ──────────────────────→ ┌──────────┐ 执行工具(可中断审批) ┐
           │  model   │                          │  tools   │◄──────────────────┘
           │ 节点(LLM)│ ←──────────────────────  │ 节点     │  ToolMessage 回灌
           └──────────┘   进入下一轮             └──────────┘
                │ AIMessage 无 tool_calls（直接作答，messages 流式出 token）
                ▼
              END（final）
  · 递归上限：config.recursion_limit = AGENT_RECURSION_LIMIT（默认 24，约 12 轮工具调用）
  · 多轮推进：CompoundTaskMiddleware（05 §1.1）在模型调用前拦截——复合问题
    （问句标记 ≥2 或"计算对象 + 溯源要求"组合）且工具轮数 < 2 时，向当次
    model 请求注入不落库的调度提醒，阻止一轮工具后就草草作答
  · 审批中断点：tools 节点执行前；requires_approval 的工具在此 interrupt，
    状态由 Checkpointer 持久化，resume 后从同一点继续（见 §3.4）
  · 任意节点异常：工具异常在适配器内转 failed ToolMessage 回灌，不炸图；
    模型/框架异常 → error 事件结束本次运行
```

### 3.2 构建与事件映射（builder.py / runner.py）

builder.py 骨架：

```python

    agent = create_agent(
        model=model,
        tools=tools,
        system_prompt=SYSTEM_PROMPT,                  # 05 §5
        checkpointer=checkpointer,
        # P1 审批：HITL_ENABLED 时对 APPROVAL_TOOLS 配置 interrupt_before=["tools"]
        # 或 HumanInTheLoopMiddleware，二选一在编码期按当时小版本定稿（见 §3.4）
    )
    return agent
```

runner.py 事件映射（`astream(stream_mode=["updates","messages"])`；LangChain 1.x 节点名为 `model`/`tools`）：

```python
async def run_agent(agent, question, run_id, enabled_tools=None):
    cfg = {"configurable": {"thread_id": run_id},
           "recursion_limit": settings.AGENT_RECURSION_LIMIT}
    yield Event("meta", {"run_id": run_id})
    step_no = 0
    async for mode, chunk in agent.astream({"messages": [("user", question)]},
                                           config=cfg, stream_mode=["updates", "messages"]):
        if mode == "updates":
            if "model" in chunk:
                ai = chunk["model"]["messages"][-1]     # AIMessage
                step_no += 1
                yield Event("step_start", {"step_no": step_no})
                if ai.content:
                    yield Event("thought", {"step_no": step_no, "content": ai.content})
                for tc in (ai.tool_calls or []):
                    if tool_needs_approval(tc["name"]):   # §3.4
                        yield Event("interrupt", {"step_no": step_no, "tool": tc["name"],
                                                  "args": tc["args"]})
                    yield Event("action", {"step_no": step_no, "tool": tc["name"],
                                           "args": tc["args"]})
            elif "tools" in chunk:
                tm = chunk["tools"]["messages"][-1]      # ToolMessage（含适配器信封）
                yield Event("observation", parse_tool_message(tm, step_no))
        elif mode == "messages":
            msg, meta = chunk
            if meta.get("langgraph_node") == "model" and msg.content:
                yield Event("token", {"delta": msg.content})
    yield Event("final", {"steps_count": step_no})
```

说明：Function-Calling 模型在调用工具那一轮 `ai.content` 常为空，thought 卡片为空时前端用"决定调用 {tool}"合成一行思考（见 06 §4.4），不伪造模型没说过的推理。

### 3.3 System Prompt 要点

- 角色：计算机网络课程助教；只回答/操作计算机网络相关内容，越界问题礼貌拒答；
- 工具选择策略：概念/原理/协议类问题 → `course_rag_query`；IP/子网/掩码计算 → `subnet_calculator`；路由查表 → `lpm_lookup`；域名到 IP/记录 → `dns_lookup`；需要多步时依次调用并在 thought 中说明原因；
- 最终回答必须基于 observation 与检索结果，计算结果要写出关键过程；中文作答。

### 3.4 人工审批机制（HITL，P1，架构先行）

- **前提**：create_agent 必须挂 Checkpointer（AsyncSqliteSaver，文件 `data/langgraph.db`）；运行时 `thread_id = run_id`，恢复时必须用同一 thread_id。
- **两种等价实现，编码期按当时 1.x 小版本定稿，优先第二种**：
  1. 编译期 `interrupt_before=["tools"]`：图在 tools 节点前暂停，`astream` 结束并带出待执行工具调用；后端发 `interrupt` 事件；审批端点收到决策后以 `Command(resume=...)`（批准：继续；改参：更新 state 中 tool_calls 参数后继续；拒绝：移除该 tool_calls 并回注一条"用户拒绝执行"的 ToolMessage）重新 `astream` 同一 thread；
  2. `HumanInTheLoopMiddleware`（create_agent 中间件）：按工具名配置审批回调，前端协议不变，后端代码更少。
- **审批范围**：仅 `requires_approval=True` 的工具触发（默认 ping_host/http_probe 等真实网络操作；本地纯计算与课程检索不触发），由 `HITL_ENABLED` 与 `APPROVAL_TOOLS` 控制。
- **SSE 生命周期**：中断即结束当前流（发 interrupt 后正常关闭）；审批后续跑是**新的 SSE 流**，首帧 `resumed` 携带 run_id，前端追加到原时间线而非新建会话。
- **超时策略**：中断状态由 Checkpointer 持久化，不占用进程连接；页面刷新后可从 agent_runs 找到"待审批"运行并继续。

## 4. 注册表扩展点设计

### 4.1 Parser 注册表（app/parsers/base.py）

```python
class ParsedDocument(BaseModel):
    title: str
    markdown: str           # 统一输出
    metadata: dict          # 如页数、表格数

class BaseParser(ABC):
    extensions: list[str]                       # 如 [".md", ".txt"]
    @abstractmethod
    async def parse(self, file_path: Path) -> ParsedDocument: ...

PARSER_REGISTRY: dict[str, type[BaseParser]] = {}

def register(parser_cls):                       # 类装饰器注册
    for ext in parser_cls.extensions:
        PARSER_REGISTRY[ext.lower()] = parser_cls
    return parser_cls

def get_parser(filename: str) -> BaseParser:    # 找不到抛 UnsupportedFormatError
```

- `text_parser.py` 注册 `.md/.txt`（utf-8，失败回退 gbk）；
- `docx_parser.py` 注册 `.docx`（段落 + 表格按文档顺序，标题样式转 `#`）；
- `pdf_parser.py` 注册 `.pdf`：pypdf 逐页 `extract_text()` 抽取文字层，页间空行分隔；加密 PDF 尝试空密码解密，失败则报"已加密需要密码"；整篇未抽到文本（扫描件）报"未提取到文本…不做 OCR"；标题取 PDF 元数据 `/Title`，缺失回退文件名；
- `pptx_parser.py` 注册 `.pptx`：python-pptx 按页抽取，首个标题页作 `# 一级标题`，其余标题作 `##`，无标题页作 `## 第 N 页`；正文段落、表格（转 markdown）、讲者备注（前缀"备注："）按页内顺序拼接；
- 解析器输出统一为 markdown 文本，由 `IngestionService` 缓存并交给 LightRAG；解析异常（含 `ValueError` 友好提示）统一记为该文档 failed+原因；
- `_markdown.py`：表格转 markdown 的共享小工具，docx/pptx 两处复用。

### 4.2 工具注册表（app/agent/registry.py）

```python
class ToolResult(BaseModel):
    status: Literal["success", "failed"]
    output: str                       # 喂回 LLM 的文本
    structured: dict = {}             # 给前端渲染的结构化结果
    elapsed_ms: int = 0

class BaseTool(ABC):
    name: str
    description: str
    args_schema: dict                 # OpenAI JSON Schema
    requires_approval: bool = False   # True 时 HITL 先审后执行（默认仅真实网络操作类）
    @abstractmethod
    async def _run(self, **kwargs) -> ToolResult: ...

class ToolRegistry:
    def register(self, tool: BaseTool): ...
    def openai_schemas(self, enabled: list[str] | None = None) -> list[dict]: ...
    def to_langchain_tools(self, rag_service) -> list:
        """适配器：把每个 BaseTool 包装成 LangChain StructuredTool/@tool：
        1) 入参按 args_schema 校验；2) 计时；3) 异常吞掉转 failed；
        4) ToolMessage 内容为统一 JSON 信封 {status,elapsed_ms,output,structured}，
           runner 据此还原 observation 事件——工具业务代码不依赖 LangChain。"""
    async def run(self, name: str, args: dict) -> ToolResult:
        # 统一：参数校验、计时、异常捕获 → failed ToolResult（不向上抛）
```

新增工具步骤：`tools/xxx.py` 实现 `BaseTool` → 在 `tools/__init__.py` 一行注册 → 完成。

## 5. LightRAG 工厂设计（app/rag/lightrag_factory.py）

- 进程级单例，FastAPI lifespan 中 `initialize_storages()`，关闭时释放；
- `llm_model_func`：用 `openai.AsyncOpenAI(base_url=LLM_BASE_URL)`（或 httpx）调 chat/completions（异步、`LLM_TIMEOUT`），把 LightRAG 的 messages 转为 OpenAI 格式；
- `embedding_func`：批量调 `{EMBEDDING_BASE_URL}/embeddings`，返回向量；
- 存储参数全部来自 settings：`working_dir`、`kv_storage="JsonKVStorage"`、`vector_storage=settings.VECTOR_STORAGE`、`graph_storage=settings.GRAPH_STORAGE`、`doc_status_storage="JsonDocStatusStorage"`、`max_graph_nodes=settings.MAX_GRAPH_NODES`（LightRAG 默认 1000 会按度数截断快照，统计与筛选都只在截断后的子图里做）；
- 领域抽取 prompt：传入计算机网络实体类型提示（如：协议、设备、层次、地址、算法、性能指标、概念），提升图谱质量；
- 对外方法：`get_lightrag()`、`ainsert_text(text)`、`aquery(question, mode)`、`get_graph_snapshot()`、`get_entity_subgraph(name, k=1)`。

### 6.1 DDL

```sql
  updated_at  TEXT NOT NULL

CREATE TABLE IF NOT EXISTS sessions (
  session_id  TEXT PRIMARY KEY,
  title       TEXT NOT NULL,
  mode        TEXT NOT NULL,           -- rag|agent

);

CREATE TABLE IF NOT EXISTS messages (

  session_id  TEXT NOT NULL REFERENCES sessions(session_id),

  kp_name    TEXT NOT NULL,
  kp_id      TEXT,
  session_id TEXT,
  run_id     TEXT,
  via        TEXT NOT NULL,
  created_at TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_kt_kp ON knowledge_touch(kp_id);
CREATE INDEX IF NOT EXISTS idx_kt_name ON knowledge_touch(kp_name);

-- 知识点物化（Task 5.5）：图谱实体的离线快照，kp_id 由实体名散列得到，
-- 重建索引后仍可复用；chapter=NULL 表示归章失败，不参与路径但保留可查。
-- docs/09 §3.2 里的 section 列暂不落地：本章只做到章级归属。
CREATE TABLE IF NOT EXISTS knowledge_node (
  kp_id        TEXT PRIMARY KEY,
  name         TEXT NOT NULL,
  entity_type  TEXT,
  chapter      INTEGER,
  description  TEXT,
  degree       INTEGER DEFAULT 0,
  doc_id       TEXT,
  source_chunk TEXT,
  built_at     TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_kn_chapter ON knowledge_node(chapter);

-- 前驱边（Task 5.5）：source 先于 target，章内由 LLM 抽取 + 代码校验后落库，保证无环。
CREATE TABLE IF NOT EXISTS prereq_edge (
  source     TEXT NOT NULL,
  target     TEXT NOT NULL,
  chapter    INTEGER NOT NULL,
  reason     TEXT,
  confidence REAL DEFAULT 0.6,
  status     TEXT DEFAULT 'auto',
  PRIMARY KEY (source, target)
);
CREATE INDEX IF NOT EXISTS idx_pe_chapter ON prereq_edge(chapter);
```

> 两张表的 NULL 都是刻意的：`knowledge_touch.kp_id` 可空，因为埋点（5.4）早于知识点物化（5.5）上线，历史触达只能先记名字、由脚本 `relink_touch_kp_ids()` 回填；`knowledge_node.chapter` 为 NULL 表示从来源 chunk 的文件路径里解析不出章号，这类知识点保留可查但不进路径图、也不进覆盖率分母。**读侧统计一律不猜**：未回填 kp_id 的触达不进覆盖率分子，宁可数字偏低。

> 另有 LangGraph Checkpointer 自管的 `data/langgraph.db`（框架私有表结构，随版本管理），与本 DDL 的 `app.db` 分离：前者负责图状态中断续跑，后者负责面向界面的展示/回放读模型，禁止互相读写对方表。

### 6.2 Repository 抽象接口（storage/repository.py）

```python
class Repository(ABC):
    async def init(self) -> None: ...
    async def close(self) -> None: ...

    # ----- documents -----
    async def upsert_document(self, meta: DocumentMeta) -> None: ...
    async def list_documents(self) -> list[DocumentMeta]: ...
    async def set_document_status(self, doc_id: str, status: str, **kw) -> None: ...
    async def delete_document(self, doc_id: str) -> None: ...

    # ----- sessions / messages -----
    async def create_session(self, mode: str, title: str) -> str: ...
    async def list_sessions(self) -> list[SessionMeta]: ...
    async def add_message(self, session_id, role, content, run_id=None) -> str: ...
    async def list_messages(self, session_id: str) -> list[MessageRecord]: ...

    # ----- agent trace -----
    async def create_run(self, session_id: str, question: str) -> str: ...
    async def append_step(self, run_id: str, step: StepRecord) -> None: ...
    async def finish_run(self, run_id, status, answer, steps_count) -> None: ...
    async def get_run(self, run_id: str) -> RunRecord | None: ...
    async def get_run_steps(self, run_id: str) -> list[StepRecord]: ...

    # ----- 知识点触达（Task 5.4） -----
    async def add_touches(self, records: list[TouchRecord]) -> int: ...
    async def lookup_kp_ids(self, names: list[str]) -> dict[str, str]: ...

    # ----- 学习路径物化（Task 5.5） -----
    async def upsert_knowledge_nodes(self, rows: list[KnowledgeNode]) -> int: ...
    async def list_knowledge_nodes(self, chapter: int | None = None) -> list[KnowledgeNode]: ...
    async def replace_prereq_edges(self, chapter: int, rows: list[PrereqEdge]) -> int: ...
    async def list_prereq_edges(self, chapter: int | None = None) -> list[PrereqEdge]: ...
    async def list_chapters(self) -> list[int]: ...
    async def touch_counts_by_kp(self, kp_ids: list[str]) -> dict[str, int]: ...
    async def touch_coverage(self) -> dict: ...          # {touched, total, rate}
    async def relink_touch_kp_ids(self) -> int: ...

    # ----- 大屏聚合（只读） -----
    async def screen_tool_stats(self) -> list[dict]: ...
    async def screen_message_trend(self, since: str) -> dict[str, int]: ...
    async def screen_run_stats(self) -> dict: ...
    async def screen_feed(self, limit: int = 20) -> list[dict]: ...
    async def screen_chapter_entities(self) -> dict[int, int]: ...
```

`screen_*` 一组只服务聚合端点、全部只读，`touch_coverage()` 的分母与 `list_chapters()`/`list_knowledge_nodes()` 同源（都只看 `chapter IS NOT NULL`），保证大屏覆盖率卡与 `#/path` 页两个数字对得上。

实现为 `SqliteRepository`（aiosqlite 单连接，`init_repo()` 在应用生命周期启动时注入、`get_repo()` 全局取用）。切换 PostgreSQL 时新增实现并在入口处替换，上层无感。

## 7. 统一错误处理策略

| 错误来源 | 处理 |
|---|---|
| 请求参数错误 | FastAPI 422，前端表单内提示 |
| 未启用格式（parser 预留位） | 文档状态 unsupported + 文案"该格式为预留接口" |
| 单篇解析/建库失败 | 该文档 failed 并记录 error，不影响其他文档与既有索引 |
| LLM 超时/鉴权失败 | SSE 发 error 事件，界面显示"模型服务异常：原因"，提供重试 |
| 工具执行异常 | registry 吞掉异常转 `ToolResult(status=failed, output=...)`，ReAct 继续 |
| 网络工具目标非法 | 工具内白名单校验失败，返回 failed observation 说明原因 |
| 步数耗尽 | 以现有观察强制收尾，final 带 `truncated=true`，界面提示 |
| 大屏单个字段取数失败 | 该字段回落到占位值（空数组/空对象/`_EMPTY_COVERAGE`）并记 warning，其余字段照常返回，前端面板保留占位文字 |
| 路径目标知识点不在物化快照 | `/api/path/plan` 返回 404 `PATH_TARGET_NOT_FOUND`，文案"请先运行构建脚本"，不用相近名字模糊匹配 |
| 触达埋点写库失败 | `touch_service` 内部吞掉异常只记 warning，问答与 SSE 流不受影响（埋点是派生数据，不值得牺牲主流程） |

统一错误响应体：`{"error_code": "...", "message": "中文说明", "detail": "..."}`，`detail` 仅开发模式返回。

```
static/
├─ index.html                  # 工作台（浅色，六个视图）

   └─ js/components/
```
