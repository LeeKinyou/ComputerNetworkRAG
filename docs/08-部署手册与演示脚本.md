# 08 · 部署手册与演示脚本

> 版本 v0.1 ｜ 2026-09-08 ｜ 适用：Windows 10/11 开发与现场演示（macOS/Linux 步骤等价）

## 1. 环境要求

| 项 | 要求 |
|---|---|
| Python | **3.12（项目锁定版本）**，无需预装：uv 可按 `.python-version` 自动下载 |
| uv | 包与虚拟环境管理工具（安装见 §2.1） |
| 网络 | 能访问 LLM API 基址（如 DeepSeek）；首次 `uv sync` 需要网络 |
| 磁盘 | ≥2GB（依赖 + 课程材料与索引） |
| 内存 | ≥8GB 即可（本项目不跑本地模型、不起数据库/容器） |
| 浏览器 | Edge / Chrome 最新版 |

**不需要**：Docker、MySQL、Redis、Neo4j、Node.js。

## 2. 首次安装（约 15 分钟）

### 2.1 获取项目并用 uv 建环境（自动准备 Python 3.12）

```powershell
cd D:\CodeWorksapce\VSCodeWorkspace\ComputerNetworkRAG

# 仅首次需要安装 uv（三选一；已装可跳过）
irm https://astral.sh/uv/install.ps1 | iex     # 官方独立安装（推荐，装完重开终端）
# 或：winget install astral-sh.uv
# 或：pip install uv

uv sync        # 按 uv.lock 创建 .venv（Python 3.12 缺失会自动下载）并安装全部依赖
```

> 项目根目录提供 `pyproject.toml`（含 `requires-python = ">=3.12,<3.13"`）、`uv.lock` 与 `.python-version`；**不要手工建 venv、不要用 pip install**，新增依赖统一 `uv add <包>`。

### 2.2 填写配置

```powershell
Copy-Item .env.example .env
notepad .env
```

`.env` 最小必填项（以 DeepSeek 为例，其他 OpenAI 兼容厂商替换基址与模型名即可）：

```ini
LLM_API_KEY=sk-你的密钥
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_MODEL=deepseek-chat
EMBEDDING_API_KEY=sk-你的密钥
EMBEDDING_BASE_URL=https://api.deepseek.com/v1
EMBEDDING_MODEL=该厂商提供的向量模型名
APP_HOST=127.0.0.1
APP_PORT=8000
```

注意：
- `.env` 不提交 git、不发给别人、不截图；
- 若厂商的对话与向量接口不是同一基址，分别填写；
- **`LLM_MODEL` 必须是"非思考"模型**：思考型模型（`deepseek-reasoner`、`Qwen/Qwen3-8B` 等）在建库抽取的长 prompt 上会生成超长思维链，单次调用超过 `LLM_TIMEOUT` 仍不返回，文档会永远停在 `parsed/processing`；
- 换模型只需改本文件并重启，不改代码。

### 2.3 启动

```powershell
uv run python main.py     # uv 自动使用项目 .venv，无需手动激活
```

或双击 `run.bat`（M4 交付物，内容等价于 `uv run python main.py`）。浏览器打开 <http://127.0.0.1:8000>。
接口文档（开发期）：<http://127.0.0.1:8000/docs>。

### 2.4 可选：挂载 LightRAG 官方控制台

自研的图谱视图够用，但 LightRAG 自带的 WebUI 有 3D 图谱、文档流水线、实体/关系编辑与官方查询接口。
它在**同一个进程内**复用同一个 LightRAG 单例，不起第二个服务、不复制存储，默认关闭：

```ini
LIGHTRAG_CONSOLE=true
# 二选一（公网服务器上必须先配，见下）
AUTH_ACCOUNTS=admin:你的密码
# LIGHTRAG_API_KEY=一串随机密钥
```

重启后：页面 <http://127.0.0.1:8000/webui/>，接口 `/lightrag-api/*`；"知识图谱"工具栏会出现「LightRAG 视图」按钮（新窗口打开；控制台本身是桌面布局，手机上可打开但偏挤，建议横屏或桌面端演示）。

> **安全要求**：控制台带删除文档、清空缓存、改写图谱实体的写接口。`AUTH_ACCOUNTS` 与 `LIGHTRAG_API_KEY` 都不配置时这些接口**完全不鉴权**——部署到公网（如云服务器）必须先配其中一项，否则保持 `LIGHTRAG_CONSOLE=false`。

## 3. 课程材料准备与建库

1. 把课程材料（md/txt/docx）放入任意目录，建议 `data/docs/`；
2. 打开"知识库管理"→ 上传（可多选排队）；观察状态：pending → parsed → indexed；
3. 首次建库会调用 LLM 抽取实体关系，**耗时与费用与文本量正属正常**，一篇万字讲义约 1–3 分钟；
4. 建库完成后到"概览"看统计、到"知识图谱"确认实体质量；
5. 若实体噪声大：在 `lightrag_factory.py` 的领域 prompt 中收紧实体类型后，对文档执行"重建索引"。

### 3.1 数据目录说明

```
data/
├─ lightrag/     # LightRAG 知识存储（JSON/NanoVectorDB/NetworkX 文件），勿手工编辑
├─ uploads/      # 上传的原始文件
├─ parsed/       # 解析后的 markdown 缓存（重建索引复用）
├─ app.db        # SQLite：会话/消息/trace/文档元数据
├─ langgraph.db  # LangGraph 检查点（中断审批续跑用，框架自管，勿手工编辑）
└─ docs/         # 建议的课程材料存放处（不被程序直接依赖）
```

## 4. 日常使用与重置

| 目的 | 操作 |
|---|---|
| 日常启动 | 双击 `run.bat` 或执行 `uv run python main.py` |
| 只清会话记录 | 删除 `data/app.db`（知识图谱不受影响，重启自动重建空库） |
| 只清审批检查点 | 删除 `data/langgraph.db`（框架状态，不影响知识与历史会话） |
| 重建全部知识 | 删除 `data/lightrag/` 后重启，在管理页逐篇重建（parsed 缓存仍在，无需重新解析） |
| 完全重置 | 删除整个 `data/` 目录后重启 |
| 迁移到另一台电脑/服务器 | 拷贝整个项目目录，**`.venv/` 不要拷**（新机执行 `uv sync` 重建）；`data/` 与 `.env` 不在 git 里，需一并带上：`data/` 带去已有知识与历史会话，`.env` 带去密钥配置。新机执行 §2.1、§2.2 即可 |
| 备份 | 复制 `data/` 文件夹即可，建议每次演示前备份一次 |

|---|---|---|---|

## 7. 常见问题（FAQ）

| 现象 | 原因与处理 |
|---|---|
| 启动报 `ModuleNotFoundError` | 未在项目目录执行过 `uv sync`，或用了系统 Python；重新 `uv sync` 并用 `uv run` 启动 |
| 端口 8000 被占用 | 改 `.env` 的 `APP_PORT`，或 `netstat -ano | findstr :8000` 找进程结束 |
| LLM 报 401/鉴权失败 | key 错或欠费；核对 `.env`，注意别留引号/空格 |
| LLM 请求超时 | 网络问题；健康检查确认；演示时切热点或本地 Ollama |
| 建库长期停在 `parsed`/`processing`，实体数不涨 | LLM 用了**思考型**模型：抽取长 prompt 单次调用超过 `LLM_TIMEOUT` 仍不返回。换非思考指令模型（§2.2），再对该文档"重建索引" |
| 日志报 `HTTP 402 ... account balance is insufficient` | 厂商余额/免费额度用尽。重启时它会连带打断 LightRAG 初始化，于是概览实体数显示 0、图谱页空白——**磁盘上的图谱文件没丢**，充值或换厂商后重启即恢复 |
| 上传 docx 后 failed | 文件损坏或为 WPS 加密文档；另存为标准 .docx；查看该文档 error 字段 |
| 上传 pdf 显示 unsupported | MVP 预留格式，先用 md/txt/docx；P1 实现后开放 |
| 图谱节点太多卡顿 | 用类型筛选/搜索缩小范围；后端 limit 默认 500 |
| Agent 一直转不出结果 | 多半是 LLM 慢；观察后端日志 run_id；超时会自动发 error，可点重试 |
| Windows 下 ping 工具不可用 | 已知限制（P1，可能需管理员），演示用 dns/http 工具替代 |
| 时间线中文乱码 | 确认终端/文件均 UTF-8；源码文件统一 UTF-8 保存 |
| 想清空所有历史重新演示 | 删除 `data/app.db` 重启；知识图谱保留 |
| `data/langgraph.db` 是什么 | LangGraph 的状态检查点文件，支撑人工审批"中断—续跑"；仍是本地文件、无需安装任何服务，删后仅丢失未完成的中断运行 |
| 审批按钮不出现 | 确认 `.env` 中 `HITL_ENABLED=true` 且工具名在 `APPROVAL_TOOLS` 内（P1 功能） |

## 8. 日志与现场排障

- 后端控制台日志带 `run_id`，Agent 出问题时按 run_id 找到对应步骤；
- 浏览器 F12 → Network → 对应 SSE 请求 → EventStream 可看到原始事件帧，用于核对前后端；
- 日志中严禁出现 key；如发现某条日志打印了 Authorization 头，按缺陷处理。
