# 08 · 部署手册与演示脚本

> 版本 v0.2 ｜ 2026-09-23 ｜ 适用：Windows 10/11 开发与现场演示（macOS/Linux 步骤等价）
> v0.2 变更：补 M5 的建库后构建步骤（§3.1）、重置与运维口径（§4）、自检清单（§5）、演示脚本重排为六分钟并让大屏与学习路径进主线（§6）、M5 排障 6 条（§7）；修正 v0.1 里 `run.bat` 的失实表述。

## 1. 环境要求

| 项 | 要求 |
|---|---|
| Python | **3.12（项目锁定版本）**，无需预装：uv 可按 `.python-version` 自动下载 |
| uv | 包与虚拟环境管理工具（安装见 §2.1） |
| 网络 | 能访问 LLM API 基址（如 DeepSeek）；首次 `uv sync` 需要网络 |
| 磁盘 | ≥2GB（依赖 + 课程材料与索引） |
| 内存 | ≥8GB 即可（本项目不跑本地模型、不起数据库/容器） |
| 浏览器 | Edge / Chrome 最新版 |

**不需要**：Docker、MySQL、Redis、Neo4j、Node.js。

## 2. 首次安装（约 15 分钟）

### 2.1 获取项目并用 uv 建环境（自动准备 Python 3.12）

```powershell
cd D:\CodeWorksapce\VSCodeWorkspace\ComputerNetworkRAG

# 仅首次需要安装 uv（三选一；已装可跳过）
irm https://astral.sh/uv/install.ps1 | iex     # 官方独立安装（推荐，装完重开终端）
# 或：winget install astral-sh.uv
# 或：pip install uv

uv sync        # 按 uv.lock 创建 .venv（Python 3.12 缺失会自动下载）并安装全部依赖
```

> 项目根目录提供 `pyproject.toml`（含 `requires-python = ">=3.12,<3.13"`）、`uv.lock` 与 `.python-version`；**不要手工建 venv、不要用 pip install**，新增依赖统一 `uv add <包>`。

### 2.2 填写配置

```powershell
Copy-Item .env.example .env
notepad .env
```

`.env` 最小必填项（以 DeepSeek 为例，其他 OpenAI 兼容厂商替换基址与模型名即可）：

```ini
LLM_API_KEY=sk-你的密钥
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_MODEL=deepseek-chat
EMBEDDING_API_KEY=sk-你的密钥
EMBEDDING_BASE_URL=https://api.deepseek.com/v1
EMBEDDING_MODEL=该厂商提供的向量模型名
APP_HOST=127.0.0.1
APP_PORT=8000
```

注意：
- `.env` 不提交 git、不发给别人、不截图；
- 若厂商的对话与向量接口不是同一基址，分别填写；
- **`LLM_MODEL` 必须是"非思考"模型**：思考型模型（`deepseek-reasoner`、`Qwen/Qwen3-8B` 等）在建库抽取的长 prompt 上会生成超长思维链，单次调用超过 `LLM_TIMEOUT` 仍不返回，文档会永远停在 `parsed/processing`；
- 换模型只需改本文件并重启，不改代码。

### 2.3 启动

```powershell
uv run python main.py     # uv 自动使用项目 .venv，无需手动激活
```

或双击 `run.bat`。**注意：`run.bat` 目前尚未创建**（v0.1 把它写成"M4 交付物"是失实记录，已登记在 §9 交付清单的未完成项里），现阶段只有上面这条命令。浏览器打开 <http://127.0.0.1:8000>。
接口文档（开发期）：<http://127.0.0.1:8000/docs>。

### 2.4 可选：挂载 LightRAG 官方控制台

自研的图谱视图够用，但 LightRAG 自带的 WebUI 有 3D 图谱、文档流水线、实体/关系编辑与官方查询接口。
它在**同一个进程内**复用同一个 LightRAG 单例，不起第二个服务、不复制存储，默认关闭：

```ini
LIGHTRAG_CONSOLE=true
# 二选一（公网服务器上必须先配，见下）
AUTH_ACCOUNTS=admin:你的密码
# LIGHTRAG_API_KEY=一串随机密钥
```

重启后：页面 <http://127.0.0.1:8000/webui/>，接口 `/lightrag-api/*`；"知识图谱"工具栏会出现「LightRAG 视图」按钮（新窗口打开；控制台本身是桌面布局，手机上可打开但偏挤，建议横屏或桌面端演示）。

> **安全要求**：控制台带删除文档、清空缓存、改写图谱实体的写接口。`AUTH_ACCOUNTS` 与 `LIGHTRAG_API_KEY` 都不配置时这些接口**完全不鉴权**——部署到公网（如云服务器）必须先配其中一项，否则保持 `LIGHTRAG_CONSOLE=false`。

## 3. 课程材料准备与建库

1. 把课程材料（md/txt/docx/pdf/pptx）放入任意目录，建议 `data/docs/`；
2. 打开"知识库管理"→ 上传（可多选排队）；观察状态：pending → parsed → indexed；
3. 首次建库会调用 LLM 抽取实体关系，**耗时与费用与文本量正属正常**，一篇万字讲义约 1–3 分钟；
4. 建库完成后到"概览"看统计、到"知识图谱"确认实体质量；
5. 若实体噪声大：在 `lightrag_factory.py` 的领域 prompt 中收紧实体类型后，对文档执行"重建索引"。

### 3.1 建库之后：生成学习路径与触达覆盖率（M5，必须手动跑）

"学习路径"页与大屏的"知识点触达覆盖率"卡不读图谱快照，读的是 `data/app.db` 里 `knowledge_node` / `prereq_edge` 两张物化表。这两张表**由脚本生成**，不跑脚本就都是空的：

```powershell
# 只物化知识点并归章，不调 LLM、零额度消耗（覆盖率卡与"章节知识点分布"图即可出数）
uv run python -m scripts.build_learning_path --all --nodes-only

# 追加章内先修边抽取（每个付费 LLM 调用一次/章；额度不足会 402/403 中止）
uv run python -m scripts.build_learning_path --all

uv run python -m scripts.build_learning_path --chapter 4   # 只重建某一章的边，省钱时用
```

- 在**仓库根目录**执行：`.env` 与 `data/lightrag` 都按当前目录解析。
- **建议先停掉正在运行的服务**再跑：脚本会在自己的进程里 `init_lightrag()`，与 :8000 同时打开同一批图谱文件，两侧都可能把对方的改动盖掉。物化本身幂等（`kp_id` 由实体名散列得出，重跑不换 ID），停服务再跑没有代价。
- 脚本每次都会无条件回填 `knowledge_touch.kp_id`（只补空值、不覆盖已有值），所以**先埋点采集、后跑脚本**都能接得上，不需要额外命令。
- 跑完**必须重启 :8000**：`knowledge_node` / `prereq_edge` / `knowledge_touch` 三张表的建表与两处触达埋点都发生在进程启动阶段，老进程既不建新表、也不认识新字段。
- 归章靠文件路径里的章号，**解析失败的文档（如第 7、9 章的 pptx，`status=failed`）没有实体，这两章在学习路径与章节下拉里必然是空的**——那是空数据的正确表现，不是页面坏了。要补就先修复那两份课件的解析（§7）并重建索引，再重跑本脚本。

### 3.2 数据目录说明

```
data/
├─ lightrag/     # LightRAG 知识存储（JSON/NanoVectorDB/NetworkX 文件），勿手工编辑
├─ uploads/      # 上传的原始文件
├─ parsed/       # 解析后的 markdown 缓存（重建索引复用）
├─ app.db        # SQLite：会话/消息/trace/文档元数据 + M5 的 knowledge_touch/knowledge_node/prereq_edge
├─ langgraph.db  # LangGraph 检查点（中断审批续跑用，框架自管，勿手工编辑）
└─ docs/         # 建议的课程材料存放处（不被程序直接依赖）
```

## 4. 日常使用与重置

| 目的 | 操作 |
|---|---|
| 日常启动 | `uv run python main.py` |
| 只清会话记录 | 删除 `data/app.db`（知识图谱不受影响，重启自动重建空库）。**注意 v0.2 起这张库里还有 M5 的三张表**：删它等于连带清掉知识点触达记录与物化出的学习路径，覆盖率会归零，重启后需重跑 §3.1 的 `--all --nodes-only` |
| 重跑学习路径物化（零额度） | 停服务 → `uv run python -m scripts.build_learning_path --all --nodes-only` → 重启。新增文档后想让路径页/章节分布跟上新图，就跑这一条 |
| 演示前想让覆盖率从 0 开始涨 | 停服务后用 SQLite 客户端对 `data/app.db` 执行 `DELETE FROM knowledge_touch;`（程序未提供入口，也不要边跑服务边改库），重启后现场问答会重新积累触达 |
| 只清审批检查点 | 删除 `data/langgraph.db`（框架状态，不影响知识与历史会话） |
| 重建全部知识 | 删除 `data/lightrag/` 后重启，在管理页逐篇重建（parsed 缓存仍在，无需重新解析）。**图谱变了要重跑 §3.1**，否则学习路径与覆盖率仍是旧图的物化结果 |
| 完全重置 | 删除整个 `data/` 目录后重启 |
| 迁移到另一台电脑/服务器 | 拷贝整个项目目录，**`.venv/` 不要拷**（新机执行 `uv sync` 重建）；`data/` 与 `.env` 不在 git 里，需一并带上：`data/` 带去已有知识、历史会话与 M5 三张表（新机重启即用，不必重跑 §3.1），`.env` 带去密钥配置。新机执行 §2.1、§2.2 即可 |
| 备份 | 复制 `data/` 文件夹即可，建议每次演示前备份一次 |

## 5. 演示前自检清单（开场前 10 分钟）

- [ ] 网络可访问 LLM 基址：访问 `/api/health?check_llm=1`，`llm=ok`
- [ ] 概览统计与预期一致（文档全部 indexed）
- [ ] 知识图谱能搜到核心实体（TCP、IP、子网、路由）
- [ ] RAG 页问一个简单概念题，5 秒内开始出字
- [ ] Agent 页点预置问题"192.168.10.137/27……"，时间线完整出现
- [ ] **确认跑的是重启后的进程**：访问 `/api/screen/overview`，返回里必须有 `coverage` 字段且 `total > 0`。缺字段 = 老进程（不报错，只是大屏那张卡会一直停在 "—"）；`total = 0` = 没跑 §3.1 的物化脚本
- [ ] 学习路径页 `#/path` 预先各章点一遍（节点渲染出来即正常）；**只有孤立节点 + "还没有前驱关系"告警条也是正常的**——那是 `prereq_edge` 还没抽（缺额度）时的真实状态，讲法见 §6
- [ ] 用 hybrid/local 模式**先问 3–5 轮**再投屏：覆盖率只统计真实问答触达，冷启动只有几个百分点；且 `naive` 模式不返回实体、不产生触达记录
- [ ] 大屏 `/screen` 提前打开一次并 F11 全屏（1920×1080 等比缩放；它是独立页面，与工作台互不影响）
- [ ] 浏览器提前打开六个视图（概览 / 知识图谱 / 学习路径 / RAG 问答 / ReAct 智能体 / 知识库管理）各加载一遍（图谱完成力导布局）
- [ ] 备好离线兜底：手机热点；若场地断网，提前用本地 Ollama 方案（P2：改 `.env` 基址为 `http://127.0.0.1:11434/v1`，模型需预先 pull）
- [ ] 备份 `data/`，必要时可带一份"已建库"的整个项目 U 盘

## 6. 六分钟演示脚本（建议逐字流程）

**主线是一个闭环，讲的时候要挑明**：现场提问 → 系统记下命中了哪些知识点 → 学习路径页对应节点变成"已触达 N 次" → 大屏 30 秒一轮轮询后覆盖率卡往上跳。这条链路上没有任何假数据，是本系统"能反映学习行为"的实证。

| 时间 | 页面 | 动作 | 讲解要点 |
|---|---|---|---|
| 0:00–0:40 | `/screen` 数据大屏（F11 全屏，独立标签页常驻投屏） | 从"核心指标"7 张卡扫到中央图谱、玫瑰图、14 日趋势、章节条形、高频实体 | "这是整套系统的运行全景：文档、实体、关系、分块是**建库成果**，会话、Agent 运行、触达覆盖率是**真实使用行为**。图谱每 5 分钟刷新一次、总览 30 秒一次，不用手动操作" |
| 0:40–1:40 | 知识图谱 `#/graph` | 缩放/拖拽，点"TCP"看详情与来源；选中后看一跳邻居高亮 | "图谱不是手工画的，是大模型从课件自动抽取；每个实体可溯源到具体文档" |
| 1:40–2:40 | RAG 问答 `#/rag` | 问"TCP 和 UDP 的区别"，先看来源卡片再看流式答案；切 hybrid/naive 对比 | "回答前先检索课件，来源可查；不同检索模式策略不同"。**这一问会写入触达记录**，后面两幕要用 |
| 2:40–4:10 | ReAct 智能体 `#/agent` | 点预置："192.168.10.137/27 属于哪个子网？网关一般设哪个地址？" | 逐步讲时间线：①思考判断是计算题 ②调子网计算器（看参数/结果/12ms）③发现还要课程概念 ④调课程检索（这一步同样记触达）⑤综合作答 |
| 4:10–4:50 | 学习路径 `#/path` | 选刚才那一章 → 指节点上的"· 已触达 N 次"角标；搜索框输入一个刚问过的概念看"必修链"卡片 | "系统知道这门课的知识点骨架和它们的前后关系；节点是**问过的/没问过的**，不是编出来的掌握度"。**若 `prereq_edge` 还没抽出来，这里只会看到孤立节点 + "还没有前驱关系"告警条——如实说明**："章内先后依赖要调大模型抽取，额度用完还没补跑，命令在 §3.1"，不要含糊带过 |
| 4:50–5:20 | `/screen` | 切回大屏，等覆盖率卡滚到新值（最多 30 秒）；顺手指一下 14 日趋势 | "刚才那几轮问答把覆盖率顶上来了——这个数字是行为数据，不是演示特效" |
| 5:20–6:00 | 知识库管理 / 历史回放 | 展示文档状态（含 failed 原因可展开）；打开刚才那次运行回放 | "全过程留痕、可回放；新增材料增量建库；解析失败的课件在图上必然是空的" |

讲完记得切回工作台标签页再谈细节，避免大屏 30 秒轮询与操作抢注意力。备用问题（若现场提问）见 05 号文档 §6 样例问题库。

**时间充裕时的备选一幕（真实网络 + 人工审批，约 40 秒）**：ReAct 智能体页点"www.example.com 解析到哪些 IP？解析用 TCP 还是 UDP？"——工具调用前先弹出审批卡片，现场演示「批准执行 / 修改参数后执行 / 拒绝」，拒绝后从断点继续作答。前提是 `.env` 里 `HITL_ENABLED=true`（默认 `false`）**且**该工具在 `APPROVAL_TOOLS` 内——默认只放了 `ping_host,http_probe`，DNS 工具的真名是 `dns_lookup`，不在这个名单里会直接执行、不弹卡。要把审批排进这一幕就改成 `APPROVAL_TOOLS=ping_host,http_probe,dns_lookup` 并重启。讲解点："真实网络操作有安全边界，人来批"。场地断网时不要排这一幕。

## 7. 常见问题（FAQ）

| 现象 | 原因与处理 |
|---|---|
| 启动报 `ModuleNotFoundError` | 未在项目目录执行过 `uv sync`，或用了系统 Python；重新 `uv sync` 并用 `uv run` 启动 |
| 端口 8000 被占用 | 改 `.env` 的 `APP_PORT`，或 `netstat -ano | findstr :8000` 找进程结束 |
| LLM 报 401/鉴权失败 | key 错或欠费；核对 `.env`，注意别留引号/空格 |
| LLM 请求超时 | 网络问题；健康检查确认；演示时切热点或本地 Ollama |
| 建库长期停在 `parsed`/`processing`，实体数不涨 | LLM 用了**思考型**模型：抽取长 prompt 单次调用超过 `LLM_TIMEOUT` 仍不返回。换非思考指令模型（§2.2），再对该文档"重建索引" |
| 日志报 `HTTP 402 ... account balance is insufficient` | 厂商余额/免费额度用尽。重启时它会连带打断 LightRAG 初始化，于是概览实体数显示 0、图谱页空白——**磁盘上的图谱文件没丢**，充值或换厂商后重启即恢复 |
| 上传 docx 后 failed | 文件损坏或为 WPS 加密文档；另存为标准 .docx；查看该文档 error 字段 |
| 上传 pdf/docx 后 failed，error 提示"未提取到文本"/"无法打开" | 扫描版 PDF 无文字层（不做 OCR）、WPS 加密或损坏文件；换带文字层的文件或另存为标准格式 |
| 上传 pptx 后 failed | 整份为图片/图形的 PPT 无文本可抽；或为 WPS 加密文件，另存为 .pptx |
| 图谱节点太多卡顿 | 用类型筛选/搜索缩小范围；后端 limit 默认 500 |
| Agent 一直转不出结果 | 多半是 LLM 慢；观察后端日志 run_id；超时会自动发 error，可点重试 |
| Windows 下 ping 工具不可用 | 已知限制（P1，可能需管理员），演示用 dns/http 工具替代 |
| 时间线中文乱码 | 确认终端/文件均 UTF-8；源码文件统一 UTF-8 保存 |
| 想清空所有历史重新演示 | 删除 `data/app.db` 重启；知识图谱保留 |
| `data/langgraph.db` 是什么 | LangGraph 的状态检查点文件，支撑人工审批"中断—续跑"；仍是本地文件、无需安装任何服务，删后仅丢失未完成的中断运行 |
| 审批按钮不出现 | 确认 `.env` 中 `HITL_ENABLED=true` 且工具名在 `APPROVAL_TOOLS` 内（P1 功能） |
| 大屏覆盖率卡一直停在 "—" | 两种情况，先用 `/api/screen/overview` 分辨：**返回里没有 `coverage` 字段** = :8000 跑的还是加这张卡之前的进程，重启即可（旧进程不报错，只是没这个字段）；**`coverage.total = 0`** = 从没跑过 §3.1 的物化脚本，前端此时会显示"尚未物化知识点"并隐藏进度条，这是设计行为不是 bug |
| 演示现场覆盖率不涨 | 只有会命中图谱实体的检索才记触达：`naive` 模式走向量分块、不返回实体，**问多少轮都不涨**；要涨用 hybrid/local/global。另注意大屏总览是 30 秒一轮轮询，不是即时的 |
| 学习路径页只有孤立节点、顶部有"还没有前驱关系"告警条 | `prereq_edge` 是空表（先修边要调 LLM 抽取，只花钱不自动跑）。按 §3.1 跑 `--all` 补边；只跑 `--all --nodes-only` 永远不会有边 |
| 路径页章节条里少了某几章 | 那几章在图谱里没有实体（多半是课件 `status=failed`，如本项目第 7、9 章的 pptx），或知识点归章失败 `chapter=NULL`。下拉只列真有知识点的章，空章不给选项是刻意的 |
| 大屏用手机看很挤 | `/screen` 按 1920×1080 等比缩放设计，手机竖屏会缩得很小；手机上要用请横屏，或直接用工作台（工作台是响应式的） |
| `build_learning_path` 报 402/403 中断 | 免费额度用尽或 key 无权。物化与回填部分不受影响（已打幂等 upsert），换 key/充值后重跑同一条命令即可，`kp_id` 不变、触达记录不会失联；只想先出覆盖率数字就加 `--nodes-only`（零额度） |

## 8. 日志与现场排障

- 后端控制台日志带 `run_id`，Agent 出问题时按 run_id 找到对应步骤；
- 浏览器 F12 → Network → 对应 SSE 请求 → EventStream 可看到原始事件帧，用于核对前后端；
- 日志中严禁出现 key；如发现某条日志打印了 Authorization 头，按缺陷处理。
