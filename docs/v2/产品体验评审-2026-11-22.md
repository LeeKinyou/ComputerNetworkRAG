# ComputerNetworkRAG 产品体验评审

- 日期：2026-11-22
- 视角：首次进入课程的学生 + 第一次带班使用的教师
- 方法：按主链路逐页核对当前页面、真实页面截图与前后端数据流；不评价代码风格，只看产品是否可信、可用、可继续扩展
- 结论：**演示完成度很高，但产品闭环尚未闭合。当前更像“能演示的智能教辅”，还不是“学生可以连续用一周的课程产品”。**

## 1. 一句话判断

这套系统的强项是“让 AI 的过程可见”：检索、步骤、引用、审批、计算卡都做得比普通问答扎实。  
但产品的主要断点不在功能数量，而在三件事：

1. **真实数据和演示数据混在一起**：API 失败时仍显示看似真实的数字和任务。
2. **学习任务没有“学”的环节**：任务大多直接跳到做题，缺少讲解/阅读/示例这一层。
3. **很多操作只停留在前端反馈**：存笔记、出题、加入今日任务、推送班级，刷新后并不存在。

## 2. 用户旅程逐段检查

| 阶段 | 现在发生什么 | 用户感受 | 主要断点 |
| --- | --- | --- | --- |
| 登录 | 输入账号口令；可展开“演示账号”一键填入教师/三名学生 | 演示方便 | 教师口令直接暴露在前端；真实班级无法加入 |
| 工作台 | 汇总今日任务、待审批、最近练习、班级覆盖 | 信息密度高，知道下一步 | “开始今天的学习”多数落到做题；计划不可调整 |
| 学习/问答 | 提问、步骤回放、引用、审批、计算卡 | 信任感强，过程透明 | 没有讲解页；回答下的动作不持久 |
| 练习 | 选择题/判断题，即时判分、解析、出处、错题本 | 反馈快，错题可重练 | 题型偏浅；一次作答就可能被标记“已掌握” |
| 作业 | 教师 Markdown 导入；学生文本作答；自动评分后教师逐题改分 | 能跑通 | 出题、发布、截止、总评、通知都不完整 |
| 报告/学情 | 真实练习趋势、章节掌握、教师概念学情 | 有数据感 | 部分图表/建议/推送是假数据或空操作 |
| 知识库 | 上传、切片预览、引用定位、删除 | 演示顺滑 | 学生也能改共享语料，权限边界错误 |
| 移动端 | 桌面侧栏在窄屏隐藏 | 桌面体验完整 | 没有抽屉/底部导航，手机上进不去其他页面 |

## 3. P0：先修“可信”，否则加功能会放大问题

### 3.1 演示数据会伪装成真实数据

- 教师学情页的“错因分布”始终读取 `mock/workbench.ts` 的固定值（概念混淆 38%、步骤遗漏 27%、计算错误 22%、读题偏差 13%），即使上方真实 API 已返回数据。
- “本周建议”是一段硬编码的“网络层块对齐”文案，不随当前班级薄弱点变化。
- “推送到班级任务”只弹一条 `已推送学习任务给 42 人` 的 toast，没有创建任何作业或任务。
- 学情页在接口失败时会回退到 mock 的 186 次提问、42 人、固定高频问题；教师无法分辨这是真实数据还是占位数据。
- 问答页在后端不可用时保留 mock 任务，并且这些任务仍可点开、显示预置答案。
- 工作台任意一个并行请求失败时，会把计划、练习、错题、待审批全部清空，页面显示“今天没有待补的知识点”，而不是报错。

**影响**：这是产品信任问题，不是样式问题。教师可能按假薄弱点备课，学生可能把演示任务当成自己的学习记录。

**建议**：
- 增加显式的 `demo` / `real` 模式；生产模式禁止 mock 回退，接口失败就显示“数据暂时不可用 + 重试”。
- 所有统计卡片标注数据来源与时间范围；没有数据就显示“暂无数据”，不要用示例数字填充。
- “推送到班级任务”要么真实创建任务，要么先移除；不要保留空操作按钮。

### 3.2 学生可以修改共享知识库

- 知识库页面对学生也显示“上传文档”和“删除这份文档”。
- 后端 `POST /courses/{id}/documents`、`DELETE /documents/{id}` 没有教师权限校验；只要登录，学生就能上传或删除非预置文档。
- 删除会同时移除分块与索引，直接影响全班问答的引用来源。

**影响**：共享 RAG 语料可被任意学生污染或删除，既是用错权限，也是产品边界不清。

**建议**：知识库写入默认教师专属；学生只读。若要做“学生补充资料”，走“提交待审核”而不是直接入库。

### 3.3 AI 回答下的动作不持久

- “存为笔记”只把一条 artifact 塞进当前前端数组，并提示“可在「我的」查看”；实际上“我的”页面没有产物/笔记区域，刷新即丢失。
- 笔记内容还固定写成“子网划分速记”，与当前问题无关。
- “出 3 道题”只生成一个本地 artifact，没有真的组卷、没有跳转、没有题目 id。
- “加入今日任务”只有 `notify('已加入今日任务')`，学习计划和工作台不会变化。

**影响**：这是产品最核心的“问答 → 产物 → 下一步行动”闭环，目前是断的。用户会以为操作成功，实际什么都没发生。

**建议**：三个动作都要落库或走真实业务接口：
- 笔记：新增 artifact/note 表，或个人资料页真实展示；
- 出题：调用组卷接口，带 `question_ids` 跳到练习；
- 加入任务：写入用户计划覆盖项，工作台即时出现。

## 4. P1：补齐“学习闭环”，而不是继续加页面

### 4.1 有问答、有练习，但没有“讲解/阅读”这一层

- 工作台的 `learn`、`review`、`practice` 任务，除了作业外全部路由到 `/practice?concept=...`。
- 知识图谱节点只有一段定义和原文出处；知识库更像管理后台。
- 学生想系统学一个知识点，只能“问 AI”或“做题”，没有“3 分钟读完这一节”的稳定路径。

**影响**：产品定位是学习工作台，但主要交互是检索问答和测评；缺少教学法里的“讲解—示例—检查—总结”。

**建议**：增加概念学习页 `/learn/:concept`：
- 学习目标、1 段短讲解、1 个例题、原文引用；
- “问 AI”“练 3 题”“标记已学”三个出口；
- `learn` 任务默认进这里，`review` 进错题/练习，`practice` 才进练习。

### 4.2 学习计划不可调整

- “重新规划”只是重新 GET 一次 `/learning/next`。
- 没有每日可用时长、目标日期、跳过/锁定任务、手动排序。
- 工作台的“调整计划”也只是跳到这个只读页面。

**影响**：计划是系统算给你看的，不是你和系统共同维护的。学生临时只有 15 分钟时无法调整，教师也无法干预。

**建议**：至少支持“今天只有 15/30/60 分钟”“跳过此任务”“锁定先修任务”；计划变更要落库并在工作台同步。

### 4.3 作业只完成了“能交能改”，还不是完整作业流

- 新建作业是粘贴 Markdown 模板导入，没有题库选题、题目预览、班级选择、附件、评分标准模板。
- 导入默认“解析后可直接发布”，缺少“存草稿 → 预览 → 定时发布”的教师安全感。
- 截止时间只用于计划排序；提交接口只校验 `closed`，不校验 `due_at`，逾期仍可提交。
- 教师逐题改分并自动生成总评，但没有“返回学生/发布成绩/通知学生”的动作；学生只能自己刷新看到分数。
- 学生提交后不能修改/重交；输入过程没有自动保存，刷新会丢草稿。

**影响**：教师不敢真用，学生也不知道“交了之后会发生什么”。

**建议**：
- 教师：题库选题 + 预览 + 存草稿/定时发布 + 班级范围；
- 学生：草稿自动保存、提交确认、截止状态（待交/已逾期/已提交/已批改）；
- 教师：总评可编辑 + 明确“发布成绩”，并产生学生端未读提醒。

### 4.4 测评深度不足以支撑“掌握度”

- 练习只有单选和判断，没有计算题输入；而子网划分正是这门课的核心计算能力。
- 图谱掌握度规则是“答过 1 题且正确率 ≥80% 即已掌握”，答错 1 题即薄弱；样本太少，标签会过度自信。
- 答题没有“不确定/跳过”，学生只能猜；猜测会污染画像和推荐。

**影响**：个性化计划、薄弱点、推荐组卷都建立在过稀的作答信号上。

**建议**：
- 增加数值/填空计算题（子网地址、可用主机数、前缀长度）；
- 掌握度引入最小样本数、近期表现和遗忘衰减；
- 增加“不确定/跳过”，不要把跳过计为答错。

### 4.5 个人数据范围存在串用

- 知识图谱加载章节统计时调用 `/practice/stats` 未带 `currentKey`，后端默认 `demo_user`；切到林晓/赵一鸣时，章节统计仍可能是李金阳的。
- 图谱节点掌握度又来自当前用户的 attempts，导致同一面板里“个人掌握度”和“他人章节统计”混在一起。
- 登录用户不在前端三名演示学生名单时，`lockStudent` 会静默失败，当前身份回退到 `demo_user`，可能看到李金阳的数据。
- 作业名单、教师班级名、42 人等仍是硬编码。

**影响**：多用户只是演示级，真实账号一接就会串数据。

**建议**：所有统计接口强制显式 `user_key` 或从登录态推导；前端未知账号要有兜底身份初始化，不能回退到 demo_user；班级/名单从数据库来。

## 5. P2：体验与规模化问题

1. **移动端没有导航**：侧栏 `hidden lg:flex`，但全站没有抽屉或底部导航；手机用户只能停留在当前页。页面内大量 9–10px 文字，移动阅读吃力。
2. **信息架构过重**：学生侧 10 个一级入口（工作台、问答、作业、练习、错题、图谱、计划、知识库、报告、我的），其中工作台/计划/作业、练习/错题/报告高度重叠。建议收敛为 5 个：首页、学习、问答、学情、我的。
3. **错误态不统一**：工作台失败清空全部数据；作业名单失败显示“还没有学生提交”；图谱/问答失败保留假数据；没有全局重试、离线提示或部分失败提示。
4. **通知缺失**：审批等待只在工作台有一张卡；作业批改、成绩发布、截止提醒都没有站内通知或徽标。异步 Agent 产品很依赖“回来处理”的提醒。
5. **帮助入口是死的**：顶栏 HelpCircle 按钮没有点击行为；新用户没有引导，第一次看到“待审批/步骤/引用”不知道该怎么用。
6. **文案与品牌漂移**：登录页叫“重邮计网教学系统”，壳内叫“智网系统”，README 叫 ComputerNetworkRAG；“我的”仍写“未接入统一认证”，但实际已有登录；README 的能力清单与现有导航也不一致。
7. **内容质量标签偏乐观**：文档只要解析成功就显示“好”，没有覆盖率、解析失败片段、引用健康度等更真实的质量信号。

## 6. 建议的优先级

### 第一阶段：可信（先做，不然越加越乱）

- demo/real 模式分离，移除生产路径上的 mock 回退；
- 知识库写入加教师权限；
- 问答三个动作真实落库/跳转；
- 修复图谱/报告的 user_key 串用；
- 所有失败态给明确提示与重试，不用假数据兜底。

### 第二阶段：闭环（决定它是不是学习产品）

- 概念学习页 + `learn` 任务正确路由；
- 计划可调（时长、跳过、锁定、目标日期）；
- 作业：题库出题、草稿/发布、截止策略、总评发布、学生通知；
- 练习：计算题、跳过/不确定、掌握度最小样本。

### 第三阶段：规模化

- 真实班级/选课/名单，替换硬编码姓名与 42 人；
- 移动端抽屉导航与 375px 适配；
- 审批/作业/成绩通知；
- 帮助中心与首次使用引导；
- 统一品牌、README 与页面文案。

## 7. 值得保留的强项

- Agent 的步骤回放、工具调用、引用与人工审批，形成了同类产品里少见的“可解释感”。
- 计算卡和原文引用把“答案”变成了“可核对的结果”，这是很好的信任设计。
- 学习计划的“先修未掌握先补前置”、推荐理由、预计分钟，产品思路是对的。
- 练习即时反馈 + 解析 + 出处 + 错题重练，闭环已经成型。
- 教师端概念粒度学情、按学生切换、CSV 导出，方向正确。
- 浅色/深色主题与整体视觉完成度高，演示观感好。

## 8. 产品验收清单（建议直接变成下一轮任务）

- [ ] 断开任意一个统计接口时，页面显示错误与重试，不出现任何 mock 数字。
- [ ] 学生账号调用文档上传/删除返回 403。
- [ ] 存笔记/出题/加入今日任务后，刷新页面仍然存在，且能从对应页面找到。
- [ ] 点击“学习”任务进入讲解页，而不是直接做题。
- [ ] 修改每日时长/跳过任务后，工作台任务同步变化。
- [ ] 教师能存草稿、预览、按班级发布作业；学生能看到逾期状态并自动保存草稿。
- [ ] 切换学生后，图谱章节统计与个人掌握度都只属于该学生。
- [ ] 375px 宽度下可以通过导航进入全部核心页面。
- [ ] 教师成绩发布后，学生端出现未读提醒。
