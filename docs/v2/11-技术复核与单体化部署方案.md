# V2 技术复核与单体化部署方案

版本：1.0。日期：2026-11-18。状态：复核结论，待用户确认后作为开发基线。

本文不改写 [00](./00-重构总设计.md)–[09](./09-三人开发分工与交付计划.md) 的产品设计，只回答三个问题：现有技术选型在当前目标下是否合适、能否单体打包快速部署、前端如何做出演示级效果。

## 0. 结论摘要

1. **技术栈主干保留**：Vue 3 + TypeScript + Vite、FastAPI、SQLAlchemy + Alembic、LangGraph 1.x 都是当前约束下的合理选择，不需要换框架。
2. **两处"必备中间件"降级为可选实现**：Redis Streams 与 MinIO 在单机演示中收益极低、成本极高。保留 `QueueAdapter` / `ObjectStorage` 端口，lite 档注入内存队列与本地文件实现，full 档仍可接真实服务。
3. **部署从"三进程 + Compose"改为"单进程 + 单端口 + 一条命令"**，已用 spike 实测：FastAPI lifespan 内嵌 worker、SSE 推送、静态页托管同时成立。
4. **前端 UI 库替换**：Element Plus 的默认观感偏后台管理系统，与"演示要精致"冲突。改用 Tailwind + shadcn-vue（备选 Naive UI），组件完全可控。
5. **MVP 范围收缩**：只保留"课程/文档 → 知识图谱 → RAG 问答 → ReAct 轨迹 → 人工审批"这一条可讲故事的链路；题库、自动批改、错题复习、多用户权限全部后置。

## 1. v2 文档的硬约束与演示目标的冲突

| 维度 | v2 原文要求 | 导师演示实际需要 | 冲突程度 |
| --- | --- | --- | --- |
| 中间件 | "两种模式都使用 Redis 和 MinIO"，"不再是可有可无的演示配置"（01 §1.2、§12） | 插电即跑，最好零外部依赖 | 高 |
| 进程模型 | api / worker / dispatcher 分进程（01 §1.3、§10） | 一个进程即可 | 高 |
| 部署 | Docker Compose，web/api/worker/dispatcher/Redis/MinIO（00 §3、08 §2） | 本机无 Docker、无 WSL；导师机器同样不确定 | 高 |
| UI | Element Plus 用于表单/管理（00 §3、07 首段） | 首屏要"精致、可展示" | 中 |
| 产品范围 | 学习工作台：登录、题库、提交、评分、错题、复习（00 §1） | 图谱 + RAG + ReAct + 审批 | 高 |
| 协议复杂度 | CSRF、Idempotency-Key、游标分页、版本 CAS、事件 seq（05） | 演示可简化，但要保留事件流 | 中 |

结论：v2 是"多用户产品"的架构，不是"演示 demo"的架构。直接照做会把 70% 工期花在演示中看不见的可靠性设施上。正确做法是**保留端口抽象，替换实现**，而不是推翻设计。

## 2. 逐项选型复核

| 组件 | 判定 | 处理 |
| --- | --- | --- |
| LangGraph 1.x（`create_agent` + checkpointer + interrupt） | 保留 | 人工审批、断点续跑、步骤流式都靠它；不手写循环 |
| FastAPI + SSE | 保留 | POST 建 run、GET 订阅事件的组合最省事，比 WebSocket 稳 |
| SQLAlchemy 2.x async + Alembic | 保留 | 已有 PostgreSQL，迁移一条 revision 即可，成本不高 |
| Redis Streams | 降级为可选 | lite 档用 `asyncio.Queue`；full 档保留 Streams 实现 |
| MinIO | 降级为可选 | lite 档用 `runtime/objects` 本地目录；full 档保留 S3 实现 |
| Vue 3 + TS + Vite + Pinia + Router | 保留 | 与现有经验一致 |
| Element Plus | 替换 | 改 Tailwind + shadcn-vue（备选 Naive UI） |
| Docker Compose | 降为可选 | 主路径改为 `uv run` 单命令；Compose 仅作为 full 档附录 |
| 进程模型 | 调整 | 默认单进程内嵌 worker；保留 `worker.py` 独立入口供 full 档 |
| 认证 / 幂等 / CSRF | 裁剪 | MVP 保留单用户会话；CSRF 与幂等键在写接口预留字段但不强制 |

### 2.1 为什么保留 LangGraph

- `interrupt()` + `Checkpointer` + `Command(resume=...)` 是现成的人工审批路径，换成手写 function-calling 循环要自己实现状态持久化、恢复、审批挂起。
- `astream(stream_mode=["updates","messages"])` 能同时拿到节点级事件和 token，正好对应"每步可视化 + 流式回答"。
- 注意 1.x 的流式节点名是 `model`（0.x 是 `agent`），事件映射时不要写死。

### 2.2 为什么降级 Redis Streams

v2 引入 Streams 是为了解决"多进程至少一次投递、租约、pending 回收"。单进程演示中：

- 只有一个消费者，投递不需要跨进程；
- 任务事实已经落在 SQL，队列只是唤醒手段；
- outbox/lease/reclaim 这一整套可靠性代码在演示中不可见，却要占大量开发和排障时间。

因此 lite 档用 `asyncio.Queue` + SQL 状态即可；`QueueAdapter` 接口不变，full 档换回 Streams 时业务代码零改动。

### 2.3 为什么降级 MinIO

演示场景的文件量是"几份课件"，没有预签名 URL、多租户隔离、对象版本化的需求。本地目录 + 相对路径写入 SQL 足够，还能避免现场网络故障导致上传失败。接口仍保留 `put/head/get/delete/create_download_url`。

### 2.4 为什么替换 Element Plus

Element Plus 的默认间距、圆角、阴影、蓝色主色是"中后台"语汇，定制只能覆盖变量，深层组件结构仍带管理系统的味道。演示首屏的观感直接决定评价，需要的是：

- 完全可控的间距/圆角/层级；
- 一致的浅色学术风；
- 少量但精确的动效。

shadcn-vue 是 headless 组件 + Tailwind，组件源码进仓库，改起来没有上限；代价是需要自己写样式。备选 Naive UI 的主题系统更成熟、上手更快，如果工期紧可以选它。

### 2.5 关于 RAGFlow 与 LightRAG

- **RAGFlow 不用**：它是独立服务，自带 MySQL/Redis/MinIO/ES 容器栈，与"单进程演示"直接冲突；知识图谱也不能方便地导出为自有数据结构。
- **LightRAG 不作为主链路**：它的自动实体关系抽取对中文课程术语的稳定性不可控，图谱质量会直接影响演示效果。建议图谱由"课程大纲 + 概念表 + 文档 chunk 映射"确定性构建，LightRAG 仅作为可选 adapter 做对照实验。
- **检索**沿用 v2 的"BM25 + 向量 + RRF"进程内方案，不引入 pgvector、ES、Neo4j。

## 3. 单体化方案

### 3.1 三档部署形态

| 档位 | 进程 | 外部依赖 | 适用 |
| --- | --- | --- | --- |
| `lite`（默认） | 1 个 FastAPI 进程，内嵌 worker | 无（SQLite + 本地文件 + 内存队列） | 导师演示、离线答辩、快速迭代 |
| `hybrid` | 1 个 FastAPI 进程，内嵌 worker | PostgreSQL + Redis + MinIO（已有远程实例） | 开发联调、验证真实链路 |
| `full`（可选） | api / worker / dispatcher 三进程 | 全套 + Compose | 多用户部署，非本轮目标 |

切换只改 `.env` 的 `DEPLOY_MODE`，业务代码不感知。

### 3.2 代码结构（端口不变，实现可换）

```text
backend/app/
  main.py                 # FastAPI + lifespan（lite/hybrid 启动内嵌 worker）
  worker.py               # 独立 worker 入口（full 档）
  infrastructure/
    queue/                # QueueAdapter: InMemoryQueue | RedisStreamsQueue
    storage/              # ObjectStorage: LocalObjectStorage | MinioObjectStorage
    database/             # UnitOfWork, engine 工厂（sqlite | postgresql）
    llm/                  # ModelGateway（OpenAI 兼容协议）
  agent/                  # LangGraph 图、工具、审批策略
  modules/                # courses / knowledge / tutoring
frontend/                 # Vue 3 + Vite，build 产物由 FastAPI 托管
runtime/                  # app.db、objects/、checkpoints.db、index-cache/
```

`main.py` 的 lifespan 负责：初始化 DB → 装载索引 → 启动内嵌 worker task → 注册关闭钩子。full 档把 worker task 换成独立进程，`main.py` 只留 API。

### 3.3 启动与分发

```powershell
# 首次
uv sync
npm --prefix frontend ci
npm --prefix frontend run build

# 日常启动（单端口 8000）
uv run python -m app.main
```

分发形态建议"源码目录 + uv"：把仓库压缩发给导师，解压后跑 `scripts/start.ps1`（内部执行上面两步）。不做 PyInstaller 单 exe：LangGraph/pydantic 存在动态导入，打包后易在目标机器上出现难排查的导入错误，收益不值得。

### 3.4 已验证的可行性（2026-11-18 实测）

用一个临时 spike 验证了单体形态的三个关键点，验证后已删除：

| 验证项 | 结果 |
| --- | --- |
| FastAPI lifespan 启动内嵌后台任务 | 通过，进程退出时任务正常取消 |
| `StaticFiles` 托管前端构建产物（SPA 入口） | 200，HTML 正常返回 |
| 同进程 SSE 推送事件 | 连续收到 3 条 `run.stage` 事件，无阻塞 |

结论：**"单进程 + 单端口 + 内嵌 worker + SSE"在当前依赖组合下成立**，不需要为了流式或后台任务拆进程。

### 3.5 边界

- 单进程只适合单用户/低并发演示；`WORKER_CONCURRENCY` 固定为 1。
- lite 档 SQLite 只允许一个进程持有，不要同时开两个实例。
- 演示机若装 Docker，可另走 full 档，不影响 lite 主路径。

## 4. 前端展示提升方案

### 4.1 设计基调

"浅色学术工作台"，不是"后台管理面板"：

| 令牌 | 值 |
| --- | --- |
| 背景 | `#F8FAFC`；卡片 `#FFFFFF` |
| 主文本 | `#0F172A`；次文本 `#64748B` |
| 主色 | `#2563EB`（强调），辅色 `#0EA5E9` |
| 边框 | `#E2E8F0`，1px |
| 圆角 | 卡片 14px，控件 10px |
| 阴影 | `0 1px 2px rgba(15,23,42,.06)`，仅卡片级 |
| 字体 | Inter + 思源黑体 / 系统字体栈 |
| 间距 | 4 / 8 / 16 / 24 / 32 |

避免：大面积渐变、彩色图标墙、每个模块都套卡片、无意义动效。

### 4.2 页面结构（四个核心页）

1. **总览**：一句话定位 + 三门课程卡 + 最近问答 + 图谱缩略图。首屏 3 秒内出内容。
2. **知识图谱**：ECharts `graph` 力导向图。节点按章节着色、大小按度数、边按"先修/包含/关联"分线型；点击节点右侧抽屉展示定义、先修链、引用原文；支持搜索高亮与路径追踪。
3. **智能问答**：三栏——会话列表 / 消息流 / 执行轨迹。消息流含流式回答、可点击的引用卡、计算结果卡；轨迹栏按 `thought → tool → observation` 时间线逐条出现，带耗时与状态色。
4. **文档与建库**：拖拽上传、解析进度、分块预览、索引发布状态。

### 4.3 让"智能"可见的三个设计

- **轨迹面板**：不要只转圈。每一步显示"正在检索课程片段""调用 subnet(192.168.10.137, /27)""命中 5 个片段，耗时 42ms"，让评审看到 Agent 在工作。
- **引用可追溯**：回答里的引用不是文字，是可点击的卡片，跳转后自动高亮命中的原文段落。
- **人工审批**：演示一个写操作（如"批量导入文档"或"发布索引"）触发 `interrupt`，弹出审批卡显示参数摘要，确认后继续。这是 v2 最有说服力的差异点。

### 4.4 动效与细节

- 流式光标、卡片入场 120ms、图谱节点选中高亮、骨架屏；
- 空态、加载态、错误态三套都要有，演示时不会露出半成品；
- 侧栏折叠、⌘K 搜索、Esc 关闭抽屉；
- 移动端只保证阅读，不追求完整交互。

### 4.5 演示准备

- 预置一门"计算机网络"课程：6 章、约 30 个概念、40–50 条关系、3 份文档（教材章节、RFC 摘要、实验手册）；
- 预置 3 条演示脚本：`/27` 子网计算追问 `/28`、跨章节概念解释、文档对比问答；
- 首页放"一键演示"入口，避免现场输入长问题；
- 提前构建前端产物，演示时不需要 `npm run dev`。
