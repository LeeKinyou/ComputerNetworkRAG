## 1. 背景与目标

导师把三件事列为 P0：

1. 作业上传与批改；
2. 智能批改简答题、计算题等主观题；
3. 学习路径构建。

现状：系统已有单选题/判断题的练习与错题本，有基于掌握度与先修关系的 `/learning/next` 建议，但**没有作业概念**，题库 `Question` 只支持 `single / judge`，答案字段是 8 字符，无法承载参考答案、评分要点与主观题得分。

P0 目标（可验收，不追求大而全）：

- 教师能在系统内创建/上传一份作业并发布，学生能在线作答并提交；
- 简答与计算题由模型按评分要点批改，给出每题得分、要点命中与评语；**模型不可用时自动降级为规则初评**，不阻塞提交；
- 批改结果回流学习路径：未交作业、低分作业成为路径上的节点，路径按"作业优先、概念补弱其次"排出本周与接下来两段；
- 教师可查看全班提交、可手动改分；学生只能看自己的提交，且看不到参考答案与评分要点。

## 2. 范围

### 2.1 P0 做

| 能力 | 说明 |
|---|---|
| 作业 CRUD | 教师建作业、发布/关闭；章节可选 |
| 题目导入 | 教师上传 `.md` / `.txt`，按固定格式解析为题目项；也支持在页面逐题填写 |
| 学生提交 | 在线逐题作答（简答/计算），可整份提交；提交幂等 |
| 智能批改 | LLM 主路径（结构化 JSON）+ 规则兜底（要点关键词 + 数值比对） |
| 教师复核 | 教师可对单题改分/改评语，来源标记为 `teacher` |
| 学习路径 | 作业节点 + 概念节点按优先级排入两阶段路径，保留原有字段兼容 |
| 权限 | 教师/学生分离，学生仅见自己的提交与批改 |

### 2.2 P0 不做（明确留给 P1）

- 图片/手写体 OCR 批改：学生上传图片仅作为附件存档，**不参与自动批改**，界面标注"待人工复核"；
- 作业文件格式兼容 `.docx/.pdf`（知识库上传已有解析能力，但作业题目导入 P0 只做纯文本，减少失败面）；
- 班级/分组、多人协作批改、查重；
- 主观题自动满分判定（模型给分一律允许教师覆盖）；
- 学习路径的人工编辑与拖拽排序。

## 3. 现状与差距

| 能力 | 现状 | P0 需要 |
|---|---|---|
| 题目类型 | `Question.type = single/judge`，`answer String(8)` | 简答、计算；参考答案长文本 + 评分要点 |
| 判分 | `practice.py` 精确匹配 | 按要点加权、部分得分、过程分 |
| 作业实体 | 无 | 作业 / 题目项 / 提交 / 提交项 |
| 路径 | `/learning/next` 仅概念任务 | 作业节点 + 阶段划分 |
| 权限 | `scoped_user_key`、`require_teacher` 已有 | 提交与批改复用同一套 |

结论：新表独立于 `Question`，不复用题库，避免把"练习判分"和"作业批改"两套语义搅在一起；`Attempt` 也不承载作业，保持错题本口径不变。

## 5. API 契约（前缀 `/api/v2`）

所有响应沿用现有错误体：`{"error": {"code", "message", "request_id"}}`。权限：`scoped_user_key` 取当前身份，教师接口额外 `require_teacher`。

### 5.1 列表

`GET /assignments?course_id=course_cn`

学生视角：

```json
{
  "items": [
    {
      "id": "asg_01", "title": "第 3 周作业：子网与 TCP",
      "chapter_title": "网络层", "due_at": "2026-11-29T15:59:00",
      "status": "published", "item_count": 5, "total_score": 50,
      "my_status": "todo", "my_score": null, "submission_id": null
    }
  ],
  "pending": 1
}
```

`my_status`：`todo / submitted / grading / graded / failed`。

教师视角追加：`submitted_count`、`graded_count`、`avg_score`、`ungraded_count`；`my_*` 字段省略。

### 5.2 创建与导入

`POST /assignments`（教师）

```json
{
  "title": "第 3 周作业",
  "description": "",
  "chapter_id": "ch_03",
  "due_at": "2026-11-29T23:59:00",
  "status": "published",
  "items": [
    {"type": "short", "stem": "...", "reference": "...",
     "rubric": [{"text": "确认接收通道", "score": 4}], "score": 10, "concept_id": "handshake"}
  ]
}
```

校验：`items` 至少 1 题；`score` 与 `rubric` 分值和必须相等（否则 400 `INVALID_RUBRIC`）；`type` 仅 `short/calc`。

`POST /assignments/import`（教师，multipart：`file` + `title?` + `due_at?`）

- 接受 `.md` / `.txt`，≤ 2 MB，UTF-8；
- 解析成功返回 `{id, item_count, warnings[]}`，`warnings` 记录"第 N 题缺评分要点，已按分值均分"这类降级；
- 解析失败返回 400 `IMPORT_PARSE_FAILED`，`details.line` 给出行号。

文件格式（P0 唯一支持）：

```markdown
# 第 3 周作业：子网与 TCP

### 题目 1 | 简答 | 10 分
TCP 三次握手中，第三次 ACK 的作用是什么？
参考答案: 客户端确认收到 SYN+ACK，证明双向通道可用，并同步序号，避免旧连接被误接受。
评分要点: 确认接收通道=4; 同步序号=3; 避免历史重复连接=3

### 题目 2 | 计算 | 10 分
192.168.10.0/27 的网络地址和可用主机数？
参考答案: 网络地址 192.168.10.0，可用主机 30 个。
评分要点: 网络地址=4; 可用主机 30=4; 块大小 32=2
```

规则：`#` 一级标题为作业标题；`### 题目 N | 类型 | X 分` 为题目分隔；`参考答案:`、`评分要点:` 为字段行；要点用 `;` 分隔、`=` 后接分值。缺要点时按分值均分并给 warning。

### 5.3 详情

`GET /assignments/{id}`

学生：题目只含 `id/ordinal/type/stem/score/concept_id`，**不下发 `reference` 与 `rubric`**；附 `my_submission`（若有）。

教师：含 `reference/rubric`，附 `stats`（提交数、已批数、平均分、需复核数）。

### 5.4 提交

`POST /assignments/{id}/submissions`（学生）

```json
{"items": [{"item_id": "ai_1", "answer": "..."}, {"item_id": "ai_2", "answer": "..."}]}
```

- 空作答允许（判 0 分），未作答的题按空串处理；
- 提交后同步批改（单题并发上限 3，整份超时 45s）；超时或模型失败 → 规则兜底，`status=graded`、`source=rule/mixed`、`needs_review=true`；
- 返回整份结果（含每题 `score/verdict/feedback/points`），学生立即可见；
- 同一作业重复提交：覆盖旧提交并重批（删除旧 `submission_items` 后重建）。

### 5.5 教师查看与复核

- `GET /assignments/{id}/submissions`（教师）：`{assignment, items:[{submission_id,user_key,status,score,max_score,source,needs_review_count,submitted_at}]}`
- `GET /submissions/{id}`：学生仅可读自己的；教师可读任意
- `PATCH /submissions/{id}/items/{item_id}`（教师）`{score?, feedback?}` → 该题 `source=teacher`、`needs_review=false`，随后按题目项重算整份总分与 `source`
- `POST /submissions/{id}/regrade`（教师）：重跑批改（用于模型恢复后补批）

错误码：`ASSIGNMENT_NOT_FOUND`、`ASSIGNMENT_CLOSED`、`NOT_SUBMITTED`、`FORBIDDEN`、`INVALID_RUBRIC`、`IMPORT_PARSE_FAILED`、`GRADER_TIMEOUT`。

## 6. 智能批改设计

### 6.1 输入与输出契约

`grader.py` 暴露纯函数 + 一个异步入口：

```python
async def grade_item(item: dict, answer: str, *, evidence: list[str] | None = None) -> dict
```

返回值：

```json
{
  "score": 4, "max_score": 10, "verdict": "partial",
  "points": [{"point": "确认接收通道", "hit": true, "score": 4},
             {"point": "同步序号", "hit": false, "score": 0}],
  "feedback": "答出确认作用，但未提序号同步与旧连接。",
  "source": "llm", "needs_review": false, "confidence": 0.78
}
```

### 6.2 LLM 主路径

- 复用 `settings.llm_base_url / llm_model / llm_api_key`（与问答同一套），`temperature=0`，`timeout=45`；
- Prompt 约束：只输出 JSON、分数按要点累加且不超过满分、计算题"数值错但过程对只给过程分"、评语 ≤60 字；
- 解析：先剥离 ```json 代码块，再取第一个 `{...}`；解析失败重试 1 次（temperature 不变，追加"只输出 JSON"）；
- 第二次仍失败 → 抛 `GraderFormatError`，由调用方降级。

### 6.3 规则兜底

`rule_grade(item, answer)`（纯函数，无网络）：

1. 要点匹配：把每个要点切成关键词集合（去停用词，长度 ≥2 的中文片段 + 数字/英文 token），命中比例 ≥ 60% 视为该要点命中；
2. 计算题附加"数值校验"：从参考答案与学生答案各提取全部数字（含小数），若学生答案缺少参考答案中的关键数值，对应要点强制不命中；
3. 得分 = 命中要点分值和；`verdict`：满分 `correct`，0 分 `wrong`，其余 `partial`；
4. `feedback` 用模板："命中 X/Y 个要点，缺少：…（机器初评，建议复核）"；
5. `source=rule`、`needs_review=true`、`confidence=0.35`。

规则兜底只做"保底不崩"，不追求准确率；它的存在是让提交永远有结果，而不是让结果可以不做复核。

### 6.4 并发、超时与降级

- 单份提交内按题目并发（`asyncio.Semaphore(3)`）；
- 整份 `asyncio.wait_for(..., 45s)`；
- 单题异常：该题降级为规则结果；全部题目都降级 → `source=rule`；部分降级 → `source=mixed`；
- 批次写入：先写 `submissions`（`grading`），再逐题写 `submission_items`，最后回写总分与 `graded`；任一步异常置 `failed` 并保留已写入部分，允许教师 `regrade`。

### 6.5 成本与延迟预算

实测（见 §9）：单题 0.9–3.7s；5 题并发 3 路，整份约 5–8s；一次批改约 1.5k tokens 输入、300 tokens 输出。演示班 3 名学生 × 5 题 ≈ 15 次调用，成本可忽略。

## 7. 学习路径构建

### 7.1 目标形态

学生打开"学习计划"看到两段：

- **本周**：`goal` 一句话（如"先把明天到期的作业交掉，再补 CSMA/CD"）+ 3–4 个任务；
- **接下来**：其余概念补弱任务，最多 4 个。

每个任务统一结构（与现有 `LearningTask` 兼容，新增 2 个字段）：

```json
{
  "kind": "assignment",            // assignment | concept
  "assignment_id": "asg_01",
  "title": "第 3 周作业：子网与 TCP",
  "action": "submit",              // submit | review | learn | practice
  "reason": "明天 23:59 截止 · 未提交",
  "minutes": 25,
  "due_at": "2026-11-29T15:59:00",
  "priority": 0
}
```

概念任务保留原字段（`concept_id/chapter_title/state/rate/attempts`），新增 `kind="concept"`。

### 7.2 排序规则（确定性，可解释）

优先级（小在前）：

1. `priority=0` 作业未提交且 `due_at` 在 7 天内（按截止时间升序，逾期单独标 `overdue`）；
2. `priority=1` 作业已批且得分率 < 60%（生成"补练"任务，挂该题 `concept_id`）；
3. `priority=2` 概念 `weak`（正确率 < 60%）；
4. `priority=3` 概念 `no_data`；
5. `priority=4` 概念 `normal`。

先修约束：概念任务入列前，若其先修概念仍 `weak/no_data`，先插先修（现有逻辑保留）。

容量：本周最多 4 个任务、总时长 ≤ 90 分钟；超出进入"接下来"。作业任务时长按 `item_count × 5` 分钟，上限 30。

### 7.3 接口

`GET /learning/next?limit=4` 扩展（不破坏现有字段）：

- 保留 `summary / recent_attempts / tasks / chapters`；
- 新增 `stages: [{key: "this_week", title: "本周", goal, minutes, tasks}, {key: "next", ...}]`；
- `tasks` 顶层仍返回"本周"的任务，避免旧前端行为突变。

`goal` 生成规则（模板，不用模型）：本周第一个任务是作业 → "先把《X》交掉，再补 Y"；否则 → "先补 X，再往后推"。

### 7.4 与作业的联动

- 学生提交后：`/learning/next` 下一次调用即反映"已完成/已批"状态；
- 得分率 < 60% 的题目按 `concept_id` 聚合，生成一条"补练"概念任务，`reason="作业错 2 题 · 正确率 40%"`；
- 作业任务点击 → 跳 `/assignments?focus={id}`。

## 8. 权限与安全

| 风险 | 处置 |
|---|---|
| 学生读参考答案 | 详情接口按角色裁剪字段；批改结果只回传要点文本与是否命中，不含参考全文 |
| 学生看他人提交 | `GET /submissions/{id}` 校验 `user_key`；教师豁免 |
| 越权建作业 | `require_teacher` |
| 重复提交刷分 | 幂等覆盖，同作业同学生只保留一条；保留 `submitted_at` 最新值 |
| 上传攻击 | 只接受 `.md/.txt`，≤2 MB，UTF-8 解码失败即 400；文件名不参与路径拼接 |
| XSS | 题干/作答/评语全部按纯文本渲染（前端不使用 `v-html`） |
| 批改不可用 | 规则兜底 + `needs_review`，不把模型失败暴露成 500 |

## 9. 验证记录（设计阶段实测）

环境：本机 PostgreSQL 演示库、`deepseek-flash`、`temperature=0`。探针脚本：`backend/runtime/_probe_grader.py`（不进仓库主链）。

| 用例 | 结果 | 耗时 | JSON 可解析 |
|---|---|---|---|
| 简答 · 完整作答 | 10/10，correct，3/3 要点 | 3.74s | 是 |
| 简答 · 只答一半 | 4/10，partial，1/3 要点 | 1.88s | 是 |
| 计算 · 完整作答 | 10/10，correct，3/3 要点 | 0.94s | 是 |
| 计算 · 数值全错 | 0/10，wrong，0/3 要点 | 1.35s | 是 |

结论：JSON 输出稳定（4/4），判分具备区分度（10/4/10/0），延迟满足同步提交（整份 5 题预计 5–8s）。**设计假设成立，按 LLM 主路径 + 规则兜底实施。**

同时确认的现状约束：

- `/learning/next` 已返回 `summary/tasks/chapters`，新增 `stages` 属向后兼容扩展；
- 鉴权已有 `scoped_user_key` 与 `require_teacher`，作业接口直接复用；
- `Question.answer` 仅 8 字符，**不复用**题库表，新表独立。

### 9.1 实现后验收（2026-11-22 实测）

| 项 | 方法 | 结果 |

## 10. 验收标准（逐条可测）

功能：

1. 教师创建 5 题作业（简答 3 + 计算 2），`total_score` 等于题目分值和；
2. 教师上传符合格式的 `.md`，一次解析出全部题目，`warnings` 为空；格式错误返回 400 且带行号；
3. 学生提交后 10s 内返回批改结果，包含每题 `score/verdict/feedback/points`；
4. 断网/模型失败时（用 mock 抛错），提交仍返回 200 且 `source=rule`、`needs_review=true`；
5. 教师改分后，该题 `source=teacher`，整份总分同步变化；
6. 学生访问他人 `submission` 返回 403；学生详情响应中不含 `reference/rubric`；
7. 路径接口返回 `stages` 两段，未交作业出现在"本周"首位，`reason` 含截止文案；
8. 作业得分率 < 60% 时，下一份路径出现对应概念的补练任务。

非功能：

9. `pytest` 全绿（既有 138 + 新增 19 = 157，已达成）；
10. `npm run build`（含 vue-tsc）通过（已达成）；
11. Playwright 全链路：教师登录 → 建作业 → 学生登录 → 提交 → 看批改 → 路径出现作业，控制台 0 error（已达成，见 §9.1）；

## 11. 风险与回滚

| 风险 | 影响 | 处置 |
|---|---|---|
| 模型输出分数漂移 | 同一答案两次分数不同 | temperature=0；教师可改分；文档标注"机器初评" |
| 批改时延抖动 | 提交等待过长 | 45s 整份超时 + 规则兜底；前端 loading 文案"批改中" |
| 导入格式不熟 | 教师上传失败 | 页面提供格式模板下载与示例；错误带行号 |
| 新表迁移 | 演示库结构变更 | 沿用 `Base.metadata.create_all` 启动建表；不改旧表字段 |
| 路径改动影响旧页 | PathPage 崩 | 顶层 `tasks` 字段保持原结构，`stages` 为增量 |

回滚：本次改动集中在新增表、新增路由与新增页面；回滚只需移除 `/assignments` 路由与菜单入口，旧练习与路径不受影响。

## 12. 实施顺序

1. 模型与 `grader.py`（纯函数先测）→ 2. 作业 API 与导入解析 → 3. 路径扩展 → 4. 种子作业 → 5. 前端页面与菜单 → 6. 全站改名 → 7. pytest → 8. build + Playwright → 9. 分模块提交。

## 附：关键取舍说明

- **为什么作业不复用 `Question`**：题库答案是单字符，主观题需要参考答案、评分要点、部分得分；混用会让练习判分逻辑被污染，错题本口径也会变。
- **为什么规则兜底而不是"失败就让老师批"**：P0 的体验底线是学生提交后必须有结果；规则结果标 `needs_review`，把不确定性显式交给教师，而不是隐藏。
- **为什么路径只加"阶段"不加新页面**：现有 `/learning/next` 与 PathPage 已被演示视频和答辩使用，增量扩展比推倒重来风险低。
