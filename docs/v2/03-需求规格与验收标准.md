# V2 需求规格与验收标准

日期：2026-10-15。状态：待实现。范围依据：[00](./00-重构总设计.md)、[01](./01-架构设计说明书.md)。责任分配见 [09](./09-三人开发分工与交付计划.md)。

## 1. 角色和范围

| 角色 | 可以做 | 数据范围 |
| --- | --- | --- |
| 未登录 | 登录、查看基础存活状态 | 不得访问课程与个人数据 |
| 学生 | 学习、咨询、练习、提交、阅读自己的报告、接受复习计划 | 已发布课程；个人对象只能访问本人 |
| 管理员 | 学生能力、账号创建、课程/文档/题库维护、任务诊断 | 内容管理权限不自动获得他人私聊和作答访问权 |

首版课程共享给所有已登录用户；草稿课程/题目仅管理员可见。暂不做选课、租户与班级。公开注册、找回密码、OCR、多模态、真实设备诊断和自动出题发布不属于 M0–M4 必交项。

正式支持题型为单选、判断、结构化 IPv4 子网计算和简答。多选、LPM/时延扩展列入后续，不在主线偷偷扩大验收范围。模型可以推荐已审核题目，不能自行发布新题或写入成绩。

## 2. 用户故事与可验证条件

| 编号 | 需求 | 验收条件 | 阶段 |
| --- | --- | --- | --- |
| AUTH-01 | 登录与退出 | 正确账号可登录；错误凭据返回统一错误；退出后旧会话不可用；写操作缺 CSRF 被拒绝 | M0 |
| AUTH-02 | 个人数据隔离 | 使用另一用户的会话/答卷/报告/run ID，GET、写入和 SSE 都返回 404；管理员也不隐式绕过 | M0–M4 |
| COURSE-01 | 学习课程 | 显示已发布课程、章节、知识点、可定位材料；空课程给出空态 | M0 |
| KNOW-01 | 导入与发布 | 管理员上传、观察 job、发布索引；学生不能上传；失败版本不取代当前已发布版本 | M1 |
| KNOW-02 | 稳定引用 | 新版本发布后，旧回答仍能打开当时的文档版本和定位；无页码时显示章节/分块 | M1 |
| CHAT-01 | 咨询和追问 | 询问 192.168.10.137/27 后追问“换成 /28 呢”，沿用 IP，重新计算且说明新掩码 | M1 |
| CHAT-02 | 缺参/无证据 | 缺少 IP 时澄清；检索失败说明工具不可用；无证据不虚构课程引用 | M1 |
| CHAT-03 | 运行与恢复 | 单会话一个活动 run；等待时可继续/取消；刷新后能恢复最终结果和事件 | M1 |
| CHAT-04 | 可验证输出 | 子网数值来自工具；不能从 IP/掩码推断实际网关；预算耗尽显示 partial 和未完成项 | M1 |
| PRACTICE-01 | 创建与保存草稿 | 创建答卷即绑定题目版本；刷新不丢已保存内容；并发修改报版本冲突 | M2 |
| PRACTICE-02 | 提示与答案隔离 | 提示级别可见并留痕；未正式提交的学生接口、工具、事件均不含答案/rubric | M2 |
| SUBMIT-01 | 显式提交 | 二次确认后冻结答案；超时重试仍为同一答卷同一首批评分任务；提交后不可修改 | M2 |
| GRADE-01 | 可追溯评分 | 单选/判断/数值确定性评分；简答逐项 rubric；分项与总分校验，模型异常不能写成 0 分有效成绩 | M2 |
| GRADE-02 | 报告版本 | 报告标记评分版本、规则/模型/提示词版本、分项依据；重评保留旧报告，默认展示最新有效版 | M2 |
| LEARN-01 | 错题与证据 | 未满分项关联受控错因、知识点与来源；重复投递不重复累计有效学习事件 | M3 |
| REVIEW-01 | 复习与再练 | 建议需显式接受才创建计划；完成后能创建新答卷；重复同题/用提示作明显标记 | M3 |
| OPS-01 | 故障可恢复 | 重复投递、worker 崩溃、Redis 丢失、SSE 重连均满足 01 的恢复约束 | M1–M4 |
| DB-01 | 双库一致 | SQLite 文件库和 PostgreSQL 全新初始化后都能完成首场景；不自动迁旧数据 | M0–M4 |

## 3. 首个端到端验收脚本

前提：两个学生 S1/S2、一个管理员、一门已发布课程、一个经人工核验的小节、至少 15 道已审核题目。种子和数据集要求见 [08](./08-开发环境与测试交付规范.md)。

1. 管理员导入小节，等待建库完成并发布索引，确认来源可定位。
2. S1 登录并从课程工作台发问“计算 192.168.10.137/27 的网络地址、广播地址、可用主机范围，并解释网关”。
3. 应得到网络地址 `192.168.10.128`、广播 `192.168.10.159`、常规可用范围 `.129–.158`、30 个主机地址；实际网关未知。回答引用存在且人工确认支持解释。
4. 追问“换成 /28 呢”，得到网络 `.128`、广播 `.143`、常规可用范围 `.129–.142`、14 个主机地址。不能继续复用 /27 的结果。
5. 选择练习，保存一份含错误的草稿，刷新后继续，读取提示，然后显式提交。
6. 重复点击/重放提交请求，仍只有一个初次有效批改。断开 SSE、刷新，最终报告可通过查询读取。
7. 查看错因、原文及先修知识，接受复习建议，完成复习后开始新答卷。旧答卷和报告保持可读。
8. S2 尝试访问 S1 的答卷、报告、run 及事件，全部拒绝；S1 查询未提交题目不能获得隐藏答案。
9. 在 SQLite 与 PostgreSQL 各执行一次，并保存实际环境、提交 SHA、结果与失败证据。

## 4. 异常体验

| 场景 | 用户看到 | 验收要点 |
| --- | --- | --- |
| Redis 不可达，事务尚未创建 | 503，可稍后重试 | 不显示虚假排队成功 |
| SQL 已创建 job，但投递失败 | 已创建的任务和排队状态 | outbox 补投；客户端用原幂等键查询/重试 |
| 模型超时/限额 | 明确失败或 partial，保留已完成项 | 不把故障当“知识库无内容” |
| 提交后评分需复核 | 待复核，无有效分数 | 不计入掌握度和错题统计 |
| 课程没有已发布索引 | 暂不可检索，可阅读课程或稍后重试 | 不使用其他课程或旧索引冒充 |
| 草稿并发保存 | 冲突提示，保留本地未保存文本 | 不覆盖服务端新版本 |
| SSE 断线 | 重连状态；可轮询当前结果 | 不发起新的 run 或撤销任务 |

## 5. 优先级和质量门槛

M0–M3 完成上述学习闭环，M4 执行故障与效果验收。安全隔离、隐藏答案隔离、确定性计算、事务幂等为发布硬门槛，必须全部通过。模型质量保留 50 个助教任务、至少 20 份人工评分样本，披露引用支持率、评分偏差和失败案例；数值目标在首轮基线评审后由负责人确定，不将尚未评测的指标写成达标结果。

性能先记录两种模式的首事件延迟、总耗时 p50/p95、token 和成本估计。没有实测前不承诺并发或 SLA。验收编号应写入对应任务、测试名或报告，便于追踪。
