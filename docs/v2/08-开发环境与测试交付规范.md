日期：2026-10-15。状态：运行骨架待 M0 实现。A 维护公共工程，B/C 补齐各自运行与测试说明。当前仓库没有 backend/frontend/deploy，以下目录、脚本和命令均为**待交付约定**。

## 1. 现阶段能做什么

先阅读文档并检查本机 Git、Python、Node、Docker 的可用性；复制配置时只在 `.env` 不存在时操作，已有文件手动合并。不要把 `.env`、旧缓存/数据、密钥或本地 `b4809-main/` 纳入 Git；不读取或修改旧目录作为本轮实现依据。

```powershell
if (-not (Test-Path -LiteralPath .env)) {
    Copy-Item -LiteralPath .env.example -Destination .env
}
```

`.env.example` 是配置字段权威模板，当前默认 PostgreSQL、本机 127.0.0.1 和明确的本地开发凭据；需先创建相应服务。SQLite/checkpoint/cache 的相对路径固定相对于项目根目录解析为绝对路径。整套容器运行时由 Compose 注入服务名地址和 runtime 卷路径，容器内部不能用 127.0.0.1 访问其他容器。同一部署所有进程共享同一个业务 SQLite 文件，checkpoint 使用另一文件。

## 3. 公共基础设施端口

下表是项目内部约定，M0 用 Protocol/DTO 实现后导出，不绑定第三方 SDK 方法签名。

| 接口 | 最小能力 | 使用方 |
| --- | --- | --- |
| UnitOfWork | async 进入、显式 commit/rollback、模块 repository | 全员；一请求/阶段独立 session |
| ActorContext | user_id/role/course_scope/installation_id | 所有业务/工具，不接受客户端身份 |
| JobService | enqueue_in_transaction、get、request_cancel | B/C；业务事务内创建 job/outbox |
| JobExecutionContext | job_id/attempt/lease_version、heartbeat、检查租约 | B/C handler；阶段写入都带 fencing |
| QueueAdapter | publish/read_group/ack/reclaim | 仅公共任务运行时；领域服务不直接碰 Streams |
| ObjectStorage | put/head/get/delete/create_download_url | B/C；首版文件通过 API 代理 |
| EventWriter | append(run_id, expected_lease_version, type, safe_payload) | B；分配 seq 与领域状态同事务协调 |
| CheckpointFactory | 按 DB_BACKEND 建 saver/执行 setup | B；实现 A/B 协作 |
| ModelGateway | structured_generate、tool_call、embedding、usage | B 主建；C 复用模型适配与超时，不另写厂商客户端 |

A 先交付可控 job handler 演示“排队 → 执行 → SQL 结果”。B/C 的早期测试可用内存替身，但集成验收必须换为真实 Redis/MinIO；禁止 mock 成功掩盖未接通服务。

## 4. 环境矩阵和健康检查

| 模式 | 服务 | 约束 |
| --- | --- | --- |
| SQLite 开发/集成 | api×1、worker×1、dispatcher×1、web、Redis、MinIO | worker 并发 1；本机 runtime 持久卷，角色租约防重复 |
| PostgreSQL 集成 | 同上 + PostgreSQL | 初始并发仍 1；M4 才验证多 worker，不以 Redis 有多个消费者就宣称支持扩容 |
| 单元/契约测试 | 纯函数、可控模型/存储/队列替身 | 不调用收费模型；不代替关键集成 |

`GET /health/live` 仅进程存活；`GET /health/ready` 返回组件状态、schema/config 指纹、installation_id，不含 DSN/密钥。就绪检查 DB/Redis/MinIO/schema/安装一致性；模型可用性另显示，不每次健康探测都调用模型。依赖异常时 readiness=503，已有只读页面可按服务策略降级。

启动校验 DB_BACKEND 枚举、所选 DSN/路径、SQLite 单实例/并发、心跳小于租约、必需对象账号和同部署指纹；连接失败禁止静默新建另一数据库。日志统一 request_id/run_id/job_id/attempt/lease_version，敏感文本脱敏。

## 5. 测试层级与责任

| 层级 | 覆盖 | 主责/时机 |
| --- | --- | --- |
| 纯函数 | 子网边界；规则评分；复习日期；受控错因标签 | B/C，各 PR |
| 服务单元 | owner、答案隔离、版本冲突、提交/评分幂等；可控模型路由与预算 | 各领域作者，各 PR |
| API 契约 | 输入输出、错误形状、状态枚举、CSRF、私有字段不存在 | 各领域作者，各接口 PR |
| 双库集成 | 文件 SQLite 和 PG 的迁移、UTC、JSON、FK、唯一/CAS、outbox/fencing | A 框架，全员补用例，合并前 |
| 真实基础设施 | Redis 重复投递/pending、MinIO 文件状态/快照发布/历史引用 | A/B，集成和发布前 |
| 前端关键交互 | 登录、草稿保存冲突、重复提交、SSE 恢复、待复核 | 页面责任人 |
| 端到端/故障 | 03 首场景，两库完整跑；worker 崩溃/Redis 丢失/恢复备份 | A 组织，B/C 执行，M4 |
| 真实模型评估 | 50 助教任务、20 人工评分样本 | B/C，版本发布前单独运行 |

后端建议 pytest + async 支持；前端采用 Vitest 和少量浏览器端到端测试，最终依赖 M0 锁定。测试目录按 unit/contract/integration/e2e 区分；真实依赖和真实模型用标记分开。CI 使用临时库/bucket/namespace，绝不能清理开发/生产数据。

关键故障用例必须观察业务事实：

1. XADD 成功后 dispatcher 标记前崩溃：消息可重复，但一个有效业务结果。
2. worker 阶段提交后 XACK 前崩溃：恢复复用阶段，不重复成绩/学习事件。
3. lease 过期新 worker 领取：旧 worker 试写被拒，不能覆盖最终结果。
4. Redis 数据丢失：从 SQL job/outbox 重投，dispatch_seq 更新，旧消息不复活任务。
5. SSE 通知丢失/重复/刷新：按 seq 补发，完整结果一致。
6. 新索引上传一半失败：当前发布指针不变；无引用对象只在宽限期后清理。

## 6. 种子、题库和评估数据

种子使用稳定业务 code/upsert，重复执行不重复创建；UUID 由服务生成或在受控 fixture 中固定。课程原文来自可使用且经人工核验的材料，注明来源和版本，不把生成文本假称为真实课件。

首个小节至少 15 题：建议 5 单选、2 判断、5 子网计算、3 简答。每题包含稳定 code、题型、题干、公开答题 schema、服务端标准/rubric、总 units、知识点映射、难度、规则版本、人工审核者和审核记录。子网包含正常边界与 /31、/32 用途约定；不为凑数量复制同一题。

建议目录：`backend/seed_data/` 保存种子，答案目录严格仅后端读取；`evals/datasets/` 保存版本化评估输入及人工标注，`evals/reports/` 保存运行报告模板。前端构建上下文、public 目录、mock API 响应和学生事件不得打包答案/rubric。评估样本不得包含真实个人数据或 API key。

每份评估报告记录提交 SHA、数据集/课程/索引版本、模型/提示词/规则版本、配置摘要、执行日期、正确率/引用支持/评分偏差、延迟与成本、失败样例和人工复核。不把空模板计作完成评测。

## 7. PR 与交付定义

分支遵循 [合作开发规范](./02-合作开发规范.md) 的 `codex/<type>/<topic>`，如 `codex/feat/a-02-identity-courses`；任务一条主线，避免三人同时改公共入口/锁文件/迁移 head。PR 写清问题、行为、关联需求编号、实际验证命令与结果、迁移影响、页面证据和已知限制。

合并前：作者完成必要测试，另一人评审权限/事务/契约；公共基础设施和跨模块 DTO 需相关使用方确认。未实现的能力标记 TODO/未交付，不能在 README 写“已支持”。不提交本地凭据，不用真实外部服务调用作为默认单测。

M0 后 A 将本文的计划命令替换为验证过的实际命令，并在运行手册记录：初始化、备份/恢复 SQL+对象清单、Redis 重建、失败重试、SQLite 忙等待、MinIO 不可用、checkpoint setup 和从空目标库切换数据库。任何清空数据命令都单独说明，不作为默认启动路径。
