# 部署与演示手册

面向交付与课堂演示：如何把系统跑起来、5–8 分钟怎么讲、出问题怎么查。

## 一、环境要求

| 项 | 要求 | 说明 |
| --- | --- | --- |
| 操作系统 | Windows 10/11（开发机）或 Linux | 脚本以 PowerShell 为主，Linux 可手动启动 |
| Python | 3.12 | 由 `uv` 自动安装与锁定，无需手工装 Python |
| uv | 最新版 | 依赖与虚拟环境管理；缺失时 `start.ps1` 会提示安装命令 |
| Node.js | 20+（仅构建前端时需要） | 已构建过 `backend/app/static` 时可跳过 |
| 数据库 | 无 | 默认 SQLite，文件在 `runtime/` 下 |
| 网络 | 可选 | 只有调用 LLM / Embedding 时需要；不填 Key 也能完整演示 |

不需要 Docker、Redis、MinIO、PostgreSQL，也不需要同时启动前后端两个进程。

## 二、首次部署

```powershell
git clone git@github.com:LeeKinyou/ComputerNetworkRAG.git
cd ComputerNetworkRAG
Copy-Item .env.example .env
.\start.bat
```

`start.ps1` 会依次完成：

1. 检查 `uv`（缺失时给出安装命令并退出）
2. 缺少 `.env` 时从模板复制，并提示 Key 是否为空
3. `uv sync` 同步后端依赖
4. `npm install`（首次）与 `npm run build`，产物写入 `backend/app/static`
5. 启动 `uv run python -m app.main`，轮询 `/api/v2/health`，就绪后打开浏览器

首次启动约 1–3 分钟（依赖下载与前端构建）；之后再次启动通常 10 秒内。

### 手动启动（不用脚本）

```powershell
cd backend
uv sync
uv run python -m app.main
```

前端改动后需要重新构建：

```powershell
cd frontend
npm install
npm run build
```

### 模型 Key

`.env` 中两个 Key 都为空时：

- 检索、图谱、计算、审批、引用、统计全部正常
- 回答由模板组织，措辞偏结构化

填入后重启服务：

- `LLM_API_KEY`：答案经模型润色，失败自动回落到模板，不影响主链路
- `EMBEDDING_API_KEY`：当前默认走本地哈希向量；把 `EMBEDDING_BASE_URL / KEY / MODEL` 三项都填上才会启用远端语义向量，重启后自动重建索引，失败整体回退哈希（`/health` 的 `vector_mode` 可确认当前是 `hash` 还是 `remote`）

`.env` 不会热加载，改完必须重启进程。

## 三、启动、停止与端口

| 操作 | 方式 |
| --- | --- |
| 启动 | 双击 `start.bat`，或 `.\start.ps1` |
| 停止 | 关闭弹出的服务窗口，或在窗口按 `Ctrl C` |
| 地址 | <http://127.0.0.1:8000> |
| 接口文档 | <http://127.0.0.1:8000/api/docs> |
| 健康检查 | <http://127.0.0.1:8000/api/v2/health> |

健康检查返回 `{"status":"ok","db_backend":"sqlite","llm_ready":false,"retriever_ready":true}`。`llm_ready` 为 `true` 表示已读到 Key。

端口被占用时，先查占用进程：

```powershell
Get-NetTCPConnection -LocalPort 8000 -State Listen | Select-Object OwningProcess
```

## 四、演示流程（约 7 分钟）

建议按「先结论、再过程、最后证据」的顺序讲，每一步都指向屏幕上的具体位置。

### 1. 工作台（30 秒）

- 打开首页，说明这是学生每天进入的入口：今天要做什么、最近产物、课程进度
- 强调右侧「lite 模式 · 单进程」标签：整套系统只有一个进程、一个端口

### 2. 知识图谱与节点联动（60 秒）

- 进入「知识图谱」，默认选中 `TCP`
- 讲线型：蓝色实线带箭头 = 先修（箭头由先修指向后继），灰色虚线 = 包含，灰色点线 = 关联，与底部图例一一对应
- 讲节点颜色：绿 = 已掌握、橙 = 薄弱、灰 = 未学，按知识点聚合真实作答计算，不是写死的
- 右栏展示：本章已答 X 题 · 正确率、原文出处、学完它下一步（如 HTTP）、相邻知识点
- 点「相关题目」进练习中心：顶部出现「按知识点组卷」徽章，只出这个知识点的题
- 说明：图谱、练习、问答共用同一套 `concept_id`，三处可以互相跳转，这是知识网状结构真正被用起来的地方

### 3. 快速检索模式（60 秒）

- 进入「智能问答」，右上模式切到「快速检索」
- 输入：`TCP 为什么需要三次握手？`
- 观察左侧任务步骤：理解 → 检索 → 组织，只有一次检索工具调用
- 答案下方出现引用卡片，右栏列出命中的课程文档与片段
- 讲解：这就是纯 RAG —— 检索到的原文 + 组织后的回答，不做额外推理

### 4. 智能体模式（90 秒）

- 模式切到「深度智能体」
- 输入：`计算 192.168.10.137/28 的网络地址、广播地址和可用主机数`
- 观察步骤：理解 → 检索 → 计算 → 组织，多了一次工具调用
- 答案里出现计算卡：网络地址、广播地址、可用范围、主机数、掩码
- 讲解：计算结果由确定性工具产生，不是模型口算；同一问题在两种模式下步骤数不同

### 5. 练习中心（60 秒）

- 进入「练习中心」，默认随机抽 10 题，顶部可切章节；从图谱跳进来时按知识点组卷（只出该概念的题）
- 题库 48 题，其中 9 道带配图（子网划分、路由聚合、三次握手、拥塞窗口、NAT、ARP、DNS 等），点图可全屏放大
- 点右上「为我推荐」：按掌握度组卷，题卡上方给出理由（例如「还没练过 UDP」）
- 用数字键 `1` 选一个选项，`Enter` 提交：立刻显示对错、解析与教材出处
- 右上「累计作答 / 正确率」随每次提交更新，右栏同步记录本组错题
- 点错题旁的「问助教」跳到问答并自动带上题干，说明练习与问答是同一条学习链路
- 答完 10 题看结果页：得分环、本组错题、再练一组
- 讲解：题库 24 题覆盖 6 章，判分是确定性规则（不依赖模型），答案与解析只在提交后下发

### 6. 人工审批（90 秒）

- 输入：`重建第 4 章索引，把新文档一起入库`
- 运行停在「等待确认」，展示审批参数（章节、范围、参数哈希）
- 点击「批准」，运行继续并完成；点「拒绝」则保持课程内容不变
- 可选加分：审批挂起时关闭服务再重启，任务仍是待审批状态（检查点落盘），批准后继续 —— 证明状态不是存在内存里

### 7. 知识库（40 秒）

- 上传一份课件（md / pdf / docx / pptx 均可）
- 展示解析后的文档行、分块数量、章节归属
- 点开右侧切片预览，说明引用片段就是从这里检索出来的
- 上传的文档可删除，预置课件受保护

### 8. 学情与报告（40 秒）

- 「学情分析」：本周提问量、智能体/快速模式占比、完成率、章节关注度、高频问题
- 「概念掌握」区块：18 个知识点逐个给正确率、作答次数、参与人数与薄弱人数，薄弱点标橙
- 「学习报告」：本周提问、工具调用次数、近 7 天趋势
- 说明：这些数字来自真实运行记录聚合，不是写死的演示数据；练习得分与错题记录也是真实落库的（报告页的掌握度条仍为示例）

### 9. 收尾（20 秒）

- 切一次深色模式
- 打开「演示大屏」（教师视图）作为结束画面
- 回到一句话：单进程部署、检索可追溯、计算可校验、写操作可审批

## 五、演示口令（可直接复制）

```text
TCP 为什么需要三次握手？
计算 192.168.10.137/28 的网络地址、广播地址和可用主机数
把 192.168.10.137 的前缀换成 /26 再算一次
重建第 4 章索引，把新文档一起入库
CSMA/CD 与 CSMA/CA 的差异
```

前两条分别适合快速检索与智能体模式；第三条适合演示「同一会话内连续追问」；第四条触发审批。

## 六、演示前准备

```powershell
cd backend
uv run python -m app.reset_demo              # 清空历史任务、消息与练习作答
uv run python -m app.reset_demo --documents  # 连同上传文档一起清掉
```

然后重启服务。课程种子（6 章、18 知识点、21 关系、3 份预置课件）会自动保留。

如需连审批检查点一起清空，删除 `runtime/checkpoints.db` 再启动。
`runtime/app.db` 可整体删除，重启后自动重建种子；这会丢失所有历史记录。

## 七、故障排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `start.bat` 一闪而过 | PowerShell 执行策略限制 | 运行 `powershell -ExecutionPolicy Bypass -File .\start.ps1` |
| 提示未找到 uv | 未安装 | `powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 \| iex"` 后重开终端 |
| 页面 404 | 前端未构建或构建产物丢失 | `cd frontend; npm run build`，或让 `start.ps1` 自动构建 |
| 接口全部 404 | Starlette 版本被升到 1.x | `uv sync` 恢复锁文件；`pyproject.toml` 已锁 `starlette>=0.46,<1.0` |
| 白屏、控制台报 chunk 加载失败 | 浏览器缓存了旧版 index | `Ctrl F5` 强制刷新 |
| 回答没有模型润色 | `LLM_API_KEY` 为空或服务未重启 | 填 Key 后重启，检查 `/health` 的 `llm_ready` |
| 审批按钮点击报错 | 该运行来自旧进程、没有检查点 | 演示前执行 `reset_demo` 清掉历史任务 |
| 上传后没有分块 | 文件是扫描版 PDF 或纯图片 | 换带文字层的文件；接口会返回 `DOCUMENT_TEXT_UNAVAILABLE` |
| `database is locked` | 同时开了多个服务进程 | 只保留一个服务窗口，或删除 `runtime/*.db-shm`、`*.db-wal` 后重启 |
| 端口占用 | 上一次服务未退出 | 关闭旧窗口，或按上文命令查 PID 后结束进程 |

## 八、交付说明

交给导师/评审时，只需要：

1. 本仓库（`v2` 分支）与 `.env`（不含真实密钥时用模板）
2. 双击 `start.bat`，等待浏览器打开
3. 无账号体系，打开即用；数据在本机 `runtime/` 下，可随时重置

不需要提供数据库、容器编排或云主机。若要在服务器上演示，把仓库拷到 Linux，装好 `uv` 后执行 `cd backend && uv sync && uv run python -m app.main`，再把 `8000` 端口暴露即可（注意不要把 `.env` 一并公开）。
