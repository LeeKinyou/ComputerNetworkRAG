# V2 数据模型与事务设计

日期：2026-10-15。状态：迁移编写前的逻辑基线。基础设施约束以 [01](./01-架构设计说明书.md) 为准；HTTP 字段见 [05](./05-API与事件契约.md)。

## 1. 通用约定

- 主键均为应用生成 UUID；外键同类型。以下表格的 `id` 代表资源主键，API 可以映射为 `run_id/job_id`。除关联表外，业务表默认有 `created_at/updated_at` UTC 时间。
- 可变聚合有 `version` 正整数，更新使用 compare-and-swap；不可变版本表禁止原地修改内容。API 时间统一为带 `Z` 的 ISO 8601。
- SQLite/PostgreSQL 使用同一 SQLAlchemy 元数据与 Alembic revision 链；时间、JSON、约束和租约的方言差异由基础设施封装。禁止业务层依赖 JSONB/ARRAY/原生 ENUM。
- 分数保存整数 `*_units`，100 units = 1 分；API 也使用 units，不混入浮点分值。所有分项 `0 <= score_units <= max_score_units`，汇总后再写有效报告。
- JSON 保存快照/非关键扩展；owner、status、FK、版本、到期时间、幂等键等查询字段独立建列。JSON 中的对象 ID 由应用验证，不以 JSON 替代关键外键。
- 个人对象按 `owner_id` 或父对象 owner 过滤，关联查询必须一路验证；管理员无默认个人数据豁免。不能先查任意记录再只在前端隐藏。
- 删除默认归档；有答卷、报告、消息引用的题目/文档版本禁止级联删除。具体保留期由 M4 运行手册登记，保留期未决定前不启用物理回收。

## 2. 实体和字段

### 2.1 A：身份、课程与公共设施

| 表 | 必要字段（除 id 和通用字段） | 约束和索引 |
| --- | --- | --- |
| users | username、normalized_username、password_hash、role、status | normalized_username UNIQUE；role=student/admin；禁用即拒绝新请求 |
| auth_sessions | user_id、token_hash、csrf_token_hash、expires_at、revoked_at | token_hash UNIQUE；不存明文凭据；user_id/expires_at 索引 |
| courses | title、description、status、version、published_index_version_id nullable | status=draft/published/archived；索引必须属于本课程 |
| chapters | course_id、parent_id nullable、title、sort_order、version | 同课程父节点；禁止目录环；(course_id,sort_order) 索引 |
| knowledge_points | course_id、code、title、description、status | (course_id,code) UNIQUE；code 为稳定种子编码 |
| prerequisite_edges | course_id、prerequisite_id、target_id、review_status | (prerequisite_id,target_id) UNIQUE；禁止自环/跨课/成环；只使用已审核边 |
| installations | id、schema_info、config_fingerprint | 单个当前安装记录；id 即 installation_id；指纹不得含凭据 |
| service_leases | installation_id、role、slot、instance_id、lease_version、expires_at | (installation_id,role,slot) UNIQUE；SQLite 各角色固定 slot=0；PostgreSQL 可多槽 |
| file_objects | bucket、object_key、sha256、size_bytes、content_type、display_name、owner_id nullable、course_id nullable、state | (bucket,object_key) UNIQUE；state=pending/ready/failed/deleting/deleted；授权必须有业务关联 |
| jobs | installation_id、kind、aggregate_id、owner_id nullable、status、dedup_key、dispatch_seq、attempt_count、lease_version、lease_owner、lease_until、heartbeat_at、next_attempt_at、cancel_requested_at、error_code、version | dedup_key UNIQUE（含安装和业务范围）；(status,next_attempt_at)、lease_until 索引 |
| outbox_events | job_id、dispatch_seq、schema_version、status、available_at、lease_owner、lease_until、version、published_at | (job_id,dispatch_seq) UNIQUE；(status,available_at) 索引 |

service_leases 的 slot 是为架构中单实例/多实例登记补充的逻辑字段；多个 worker 不能仅靠“同 role 只有一行”表示。job 租约与进程角色租约是两件事。

| 表 | 必要字段 | 约束和索引 |
| --- | --- | --- |
| documents | course_id、chapter_id nullable、title、status、version | 文档逻辑身份；章节必须属于课程 |
| document_versions | document_id、version_no、original_file_id、parsed_file_id nullable、content_hash、parser_version、status、first_published_at nullable | (document_id,version_no) UNIQUE；ready 内容不可变；hash 去重限定课程和解析策略 |
| source_chunks | document_version_id、ordinal、section_path、page nullable、slide nullable、text、content_hash、parser_version | (document_version_id,ordinal) UNIQUE；稳定引用 ID；page/slide 从 1 开始 |
| chunk_concepts | chunk_id、concept_id、review_status | (chunk_id,concept_id) UNIQUE；同课程校验 |
| index_versions | course_id、version_no、manifest_file_id、source_versions_json、embedding_model、dimensions、algorithm_version、status、version | (course_id,version_no) UNIQUE；status=building/ready/published/retired/failed |
| chat_sessions | owner_id、course_id、title、history_summary、summary_message_range、version | (owner_id,updated_at) 索引；摘要保留消息范围 |
| messages | session_id、run_id nullable、role、content_json、turn_no | (session_id,turn_no,role) UNIQUE；role=user/assistant；保留原文，不覆盖为摘要 |
| agent_runs | session_id、owner_id、job_id、mode、context_refs_json、status、current_attempt_no、graph_thread_id、next_event_seq、pending_input_json、result_json、error_code、version | job_id UNIQUE；(owner_id,created_at)；next_event_seq 初始 1 |
| active_session_runs | session_id、run_id | session_id PK；run_id UNIQUE；FK 到会话和 run |
| agent_events | run_id、seq、type、payload_json、schema_version、lease_version | (run_id,seq) UNIQUE；按 seq 升序读取；无内部思维链 |
| agent_artifacts | run_id、type、content_json nullable、file_id nullable | 内容与文件引用至少一个；只允许学生安全 DTO |
| run_attempts | run_id、attempt_no、job_lease_version、graph_thread_id、status、stage_results_json | (run_id,attempt_no) 和 graph_thread_id UNIQUE；保留旧尝试审计 |

`run_attempts` 是对架构“每个执行 attempt 独立图线程”的落地补充。`agent_runs.graph_thread_id` 仅指当前 attempt，不替代历史。等待用户续跑复用当前 attempt；worker 失联重试创建新 attempt。

索引发布在同一短事务检查产物 ready、同课程、模型一致后切换 `courses.published_index_version_id`，更新版本状态及源文档版本的 first_published_at（只写首次时间）。学生仅可访问发布过且未被禁止访问的版本，ready 本身不授予可读权限。旧版本不能因“非当前”而失去历史引用能力。

### 2.3 C：练习、评分与学习反馈

| 表 | 必要字段 | 约束和索引 |
| --- | --- | --- |
| questions | course_id、chapter_id nullable、status、version | 逻辑题目；发布内容在版本表 |
| question_versions | question_id、version_no、type、stem_json、options_json、answer_schema_json、answer_key_json、rubric_json、max_score_units、grading_policy_version、review_status | (question_id,version_no) UNIQUE；发布版本不可变；答案/rubric 仅服务端和管理员 Schema |

| attempt_items | attempt_id、question_version_id、ordinal、answer_json、grading_snapshot_json、max_score_units、hint_level_used、version | (attempt_id,ordinal) UNIQUE；题版本/标准快照由服务端填充，不接受客户端 |
| grading_runs | attempt_id、job_id、revision_no、status、policy_version、model_id nullable、prompt_version nullable、input_refs_json、result_json、total_score_units nullable、max_score_units、review_status | (attempt_id,revision_no) UNIQUE；job_id UNIQUE；有效总分范围检查 |
| active_grading_runs | attempt_id、policy_version、grading_run_id | (attempt_id,policy_version) PK；grading_run_id UNIQUE；终态释放 |
| grading_items | grading_run_id、attempt_item_id、criterion_results_json、tool_result_json、score_units、max_score_units、error_tags_json、evidence_refs_json | (grading_run_id,attempt_item_id) UNIQUE；检查得分范围 |
| learning_events | owner_id、course_id、concept_id、type、source_type、source_id、effective、payload_json、occurred_at | (owner_id,type,source_id,concept_id) UNIQUE；(owner_id,concept_id,occurred_at) 索引 |
| concept_states | owner_id、concept_id、sample_count、recent_summary_json、last_practiced_at、version | (owner_id,concept_id) UNIQUE；派生数据，可重算 |
| review_plans | owner_id、course_id、origin_key、status、accepted_at、version | (owner_id,origin_key) UNIQUE；status=active/completed/cancelled |
| review_plan_items | plan_id、concept_id、source_attempt_item_id nullable、stage、due_at、status、completed_at、version | (plan_id,concept_id,stage) UNIQUE；status=pending/completed |

`active_grading_runs` 用跨库一致的占位约束防止活动批改并发，不依赖数据库专属的部分唯一索引。错题列表从“最新有效评分的未满分项”查询，不另建可失同步的错题事实表。

重评时保留历史 learning_events，但将旧有效贡献设为非当前，按同一 attempt_item 仅统计最新有效报告；不得因 revision 增加而增加独立样本数。复习计划历史不删除。

### 2.4 公共请求去重

`idempotency_records`：owner_id、operation、key、request_hash、resource_type、resource_id、response_status、response_json、created_at，UNIQUE(owner_id,operation,key)。只缓存学生安全的响应，不能缓存明文登录凭据。

业务创建和去重记录同事务提交；并发唯一冲突后重读。相同 key/相同请求返回原资源，相同 key/不同请求返回 409。长期任务创建、提交、继续、接受计划等使用该机制；正式提交还用 attempts 状态和 initial_grading_run_id 提供不同 key 下的业务幂等。首版不自动清除这类写请求去重记录；后续保留期变更需单独设计，不能导致旧请求重新执行。

## 3. 评分标准与学习证据细化

rubric_json 统一为 `{version,criteria:[{code,description,max_score_units,scorer,expected,evidence_requirements}]}`，criterion code 在题版本内唯一，分项满分之和等于题目满分。scorer=exact_choice/boolean/subnet_field/model_rubric；expected 是服务端标准，不能放入学生 answer_schema。

单选/判断完全匹配得该项满分，否则 0；不做模糊选项匹配。子网结构化字段逐项规范化后精确比较，地址和整数由 subnet 核心计算；过程点评默认不影响数值分。若种子题明确设置过程分，则作为独立 model_rubric 项，不能让模型改动数值项得分。简答题逐项 model_rubric，记录学生文本中的依据；不以模型给出的总分替代服务端汇总。

模型返回未知 criterion、越界/非整数 units、缺项、引用错误或无法解析时，最多一次受预算约束的格式修复；仍不合法进入 needs_review，不发布有效分数、不更新 concept_states。需要重新批改或人工复核时发布新 revision，初版不提供跨用户人工复核入口。报告中保存工具结果和模型/规则/提示词版本。

错因首批标签：mask_conversion、network_host_bits、boundary_address、unit_conversion、concept_missing；允许空列表，禁止模型任意新增标签。掌握摘要仅展示近期最多 10 个不同逻辑题目的有效作答、正确情况、用提示/重复标记和样本数；少于 3 个不同题目显示 evidence_insufficient=true。重复同题保留练习历史但不增加独立样本数，不输出未经校准的掌握概率。

## 4. 状态机

| 聚合 | 合法转换 | 特殊约束 |
| --- | --- | --- |
| job | queued → running → succeeded/failed/cancelled；running → retry_wait/waiting；retry_wait → queued；waiting → queued/cancelled | dispatch_seq 每次重投/续跑递增；attempt_count 仅新的执行尝试增加 |
| Agent run | queued → running → waiting_user/waiting_approval/completed/partial/failed/cancelled；等待 → queued/cancelled | 等待占住 active_session_runs；新消息不得绕开 |
| attempt | draft → submitted | 提交不可逆；取消 UI/SSE 不取消答卷 |
| grading run | queued → running → completed/needs_review/failed | needs_review 不产生有效成绩；修复/复核通过新 revision 发布 |
| file | pending → ready/failed；ready → deleting → deleted | 只有 ready 可被业务正式引用；删除前检查历史引用 |

Agent partial 对应 job succeeded，表示执行有终态结果而任务覆盖不完整；needs_review 同样可以对应 job succeeded，不能自动转成有效分数。基础设施失败 job failed 对应领域 failed。内部 job retry_wait 对前端 run 可保持 queued/running 并显示重试阶段。

## 5. 关键事务

| 操作 | 同一个 SQL 事务内完成 | 事务外动作 |
| --- | --- | --- |
| 创建 run | 校验 owner/课程，抢 active_session_runs，写用户消息/run/job/outbox/去重记录 | dispatcher XADD；API 返回后订阅 SSE |
| 保存草稿 | 校验 owner/draft/version，更新 answers，增加 attempt.version | 无模型调用 |
| 正式提交 | 再校验版本与必填，冻结 answers 和标准快照，写 submitted、grading_run、占位、job、outbox、去重记录 | worker 评分 |
| 发布评分 | 校验 job lease_version 和分项，写 report/items，更新 latest_valid 指针、学习事件，释放占位，完成 job | 通知前端；大报告对象先上传校验，再引用 |
| 结束 Agent | 校验租约，写完整回答/消息/终态事件，释放活动会话，完成 job | XACK、Pub/Sub |
| 等待/继续 | 等待保存 pending_input 和阶段结果；继续验证 input_id/version 并写新 outbox/dispatch_seq | 同 attempt checkpoint 恢复；确认本轮旧消息 |
| 租约回收 | 条件更新租约版本，记录新 attempt、dispatch_seq 与 outbox | 旧 worker 所有晚到提交被 fencing 拒绝 |

事件序号在更新 agent_runs.next_event_seq 的同一短事务分配；不得用 `MAX(seq)+1`。所有 worker 写业务结果/事件的方法都接收预期 lease_version，不能只在领取时检查一次。

取消 queued/waiting 的 Agent 可在事务中终结并释放占位；running 只记 cancel_requested_at，由 worker 在安全边界终结。取消与完成并发使用 version 条件更新，已完成结果保持终态。

SQL、checkpoint、Redis、MinIO 不共享事务。模型或文件网络调用不能占用业务事务。中断后先查已提交阶段结果；未引用的对象进入宽限期清理，不能通过重放图节点重复写成绩。

## 6. 迁移实施顺序

1. A：installation、identity、课程、file_objects、jobs/outbox/去重与角色租约。
2. B：文档/分块/索引、会话/run/事件；C：题目/答卷/评分/学习。B/C 在 A 合并后依次 rebase revision，由 A 串接为单一 head，不让三人各发布独立 head。
3. courses 当前索引指针、attempts 评分指针等循环依赖在关联表建立后补约束；使用可移植命名约束和 SQLite batch 迁移，不能随意关闭外键绕过。
4. 每个 revision 在两库空库升级、上个版本升级验证；模型元数据测试检查 FK/索引。涉及不可逆数据删除必须另写迁移说明和备份/恢复步骤。

不使用 `create_all` 代替正式迁移；checkpoint setup 与业务迁移分开。源码字段变更须同时修改本文和 DTO；测试至少覆盖唯一冲突、owner、UTC、外键、版本冲突、重复写与失去租约。
