# 鉴权与 IDOR 修复说明（2026-11-22）

## 问题

改造前所有 `/api/v2/*` 接口都不校验身份，`user_key` 完全由客户端 query/body 自报。任何人把 `user_key` 改成 `demo_user` / `stu_lin` 就能读别人的会话、错题、学习报告，属于典型 IDOR（越权访问对象）。

## 方案

按「角色隔离 + 环境变量固定账号」实现，不新建 users 表、不引入新依赖（只用标准库 `hmac` / `base64` / `json`）。

- **身份来源**：`AUTH_ACCOUNTS`，格式 `username:role:password`，多条用 `;` 或换行分隔；role 只接受 `teacher` / `student`。
- **口令校验**：`hmac.compare_digest` 常量时间比较，避免时序侧信道。
- **登录态**：`HMAC-SHA256` 签名 cookie（`cnrag_session`），payload 含 `sub/role/key/exp`，有效期 8 小时；`httponly`、`samesite=lax`、`path=/`。同时兼容 `Authorization: Bearer`。
- **中间件**：`/api/*` 默认要求登录，白名单仅登录、自身身份、退出、健康检查与文档；非 `/api/` 路径（静态资源、SPA）放行。
- **越权拦截**：query 与 body 两条入口都校验——学生只能操作自己的 `user_key`，教师可以指定任意学生；`/analytics/students` 只有教师可读。
- **关闭开关**：`AUTH_ENABLED=false` 时回退到旧的演示行为（按请求里的 `user_key`，缺省 `demo_user`），保留本地快速演示能力。

`/analytics/overview` 保留登录用户可读，但学生只统计自己的 run 记录；工作台上的「班级」卡片对学生隐藏。

## 账号（写入 `.env`，`.env.example` 同步，部署前须改口令）

| 用户名 | 角色 | 口令 | user_key |
| --- | --- | --- | --- |
| teacher | teacher | teacher2026 | teacher（提问记在教师名下，不进学生统计） |
| demo_user | student | demo2026 | demo_user（李金阳） |
| stu_lin | student | lin2026 | stu_lin（林晓） |
| stu_zhao | student | zhao2026 | stu_zhao（赵一鸣） |

`.env` 里的 `APP_SECRET_KEY` 已非空，签名不会退化为 `dev-secret`。

## 接口变化

新增：

- `POST /api/v2/auth/login` → `{authenticated, user}`，失败 `401 INVALID_CREDENTIALS`
- `GET /api/v2/auth/me` → `{authenticated, auth_enabled, user}`，未登录也返回 200
- `POST /api/v2/auth/logout` → 清 cookie

收紧：

- 11 个带 `user_key` query 的接口改为服务端解析身份，不再信任客户端；跨身份访问返回 `403 FORBIDDEN`
- `create_session` / `create_run` / `create_attempt` 三处 body 的 `user_key` 默认值由 `"demo_user"` 改为 `None`，避免「没传」和「冒充 demo_user」无法区分
- `GET /analytics/students` 加教师校验
- `GET /health` 增加 `auth_enabled`

## 前端

- 新增 `/login`（`meta.bare`，不套 AppShell），含演示账号一键填入
- `client.ts`：所有请求带 `credentials`，非登录接口的 401 触发回登录页并保留 `redirect`
- 路由守卫：未登录只能到 `/login`；学生访问 `/insights` 重定向回工作台
- `AppShell`：教师显示「师 + 学生下拉」，学生显示「姓名 · 学生」只读；右上角退出按钮；学生侧栏不显示「教师视图」
- 学生登录后 `user_key` 在前端被锁定，改 localStorage 也不会发出他人请求（服务端仍会 403 兜底）

## 验证

单元测试：`pytest -q` → **138 passed**（新增 `tests/test_auth.py` 7 条鉴权契约）。

真实 HTTP（`backend/runtime/_auth_smoke.ps1`）：

```
匿名 GET /learning/next              401  UNAUTHORIZED
学生登录 stu_lin                     200  role=student key=stu_lin
学生读自己（不带 user_key）            200  user_key=stu_lin
学生读他人 learning/next              403  FORBIDDEN
学生读教师接口                        403  FORBIDDEN
教师登录                             200  role=teacher
教师读全班名单                        200  total=3
教师切到 stu_lin                     200  user_key=stu_lin
教师切到 demo_user                   200  user_key=demo_user
学生退出                             200
退出后再次读取                        401  UNAUTHORIZED
错误口令登录                          401  INVALID_CREDENTIALS
```

浏览器冒烟（`backend/runtime/_auth_ui.cjs`，1440×960，无控制台错误）：

```

学生登录              → /，顶栏「林晓 · 学生」，侧栏无「学情分析」
学生刷新              → 仍在 /，身份保持
学生访问 /insights     → 被弹回 /
```

构建：`npm run build`（含 `vue-tsc`）通过，产物写入 `backend/app/static`。

## 已知边界

- 退出登录只清浏览器 cookie；服务端无会话表，已签发的 token 在 8 小时内仍然有效。演示足够，生产需要加吊销名单或改短 TTL + 刷新。
- 账号来自环境变量，改账号需重启进程。
- 演示账号口令写在前端登录页的快捷按钮里（仅便于答辩演示），正式部署应删除该区块并改掉 `.env` 口令。
